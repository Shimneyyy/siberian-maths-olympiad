# Личный кабинет Сибирской математической олимпиады

Next.js 16 / React 19 / TypeScript / Tailwind 4 / shadcn-style UI / PostgreSQL 17 /
Prisma 7 / Better Auth. Ровно три роли: студент, главный организатор, организатор площадки.

## Что работает

Учебная регистрация, подтверждение email кодом, вход/выход, восстановление пароля,
защищённый кабинет и TOTP. Главный организатор назначает/отзывает организаторов
своих площадок после повторной проверки пароля. Год и площадка проверяются сервером.
Существующего студента нельзя повысить этой операцией: совмещения ролей нет.

Ежегодное участие, управление площадками, команды, объявления, результаты, дипломы
и выдача данных nsuhw ещё не реализованы. Связь сайтов — только переход на nsuhw.ru;
его аккаунт будет сохраняться между годами. Реальные ПДн пока не принимаются.

## Локальный запуск

Нужны Node.js 24, npm, Docker Compose. Команды — в корне checkout:

```sh
npm ci
npm run dev:setup
docker compose up -d --wait
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

`dev:setup` создаёт игнорируемый Git файл `.env` из примера и случайный секрет
Better Auth, сохраняя существующие настройки и непустой секрет. Значение не печатается.
Для учебной регистрации установите `DEMO_REGISTRATION="true"` в `.env` и перезапустите
приложение. Используйте только вымышленные ФИО и email `@example.test`.
В production регистрация закрыта независимо от этого флага.

Скрипт seed повторяем: создаёт только демонстрационный вуз и курс, без пользователей
и реальных согласий. Почта направляется в Mailpit: SMTP 1025, интерфейс 8025.
PostgreSQL — порт 5432. Сервисы Compose привязаны к loopback; реквизиты примера —
только для локальной разработки. Для остановки с сохранением БД: `docker compose stop`.

Необходимы registry.npmjs.org и binaries.prisma.sh. Сетевой блокер Prisma снят;
TLS и проверка checksum сохранены. При восстановлении новой среды запустите Compose
и приложение заново: процессы не являются частью snapshot.

## Проверки

Только отдельная локальная/CI БД с синтетическими данными — никогда production:

```sh
npm run lint
npm run typecheck
npm run test:db
npm run test:http
npm run build
npm start
```

`test:db`: семь проверок БД, областей доступа, назначений и bootstrap CLI.
`test:http`: два сквозных сценария через собственный dev-сервер на порту 3100 и
локальный Mailpit, с созданием/очисткой синтетических аккаунтов. Перед ним остановите
другой `next dev` в этом checkout; тесту нужен свободный порт и доступная БД.
HTTP-набор очищает локальные rate-limit fixtures; не запускайте его в общей среде.

`GET /api/health`: 200 при доступной БД, 503 при недоступной, без подробностей ошибок.
`GET /api/me`: только текущий подтверждённый пользователь, без токена сессии;
чужая/отозванная сессия получает 401. `/cabinet` перенаправляет гостя на вход.
Для изменения схемы: `npm run db:dev -- --name <name>`; миграцию коммитить.
В CI те же проверки с отдельной PostgreSQL и Mailpit. Локальный успех не является
подтверждением результата удалённого запуска GitHub Actions.

## Учебный главный организатор

Сначала создайте синтетический выпуск через `npx prisma studio` (UI управления
выпусками — следующий этап). Затем выполните:

```sh
npm run staff:bootstrap -- chief@example.test "Тестовый главный организатор" UUID_ВЫПУСКА
```

Команда повторяема, не создаёт пароль и не добавляет новую роль. Существующего
студента или организатора площадки она не повышает. Дальше: восстановление пароля,
код подтверждения email из Mailpit, вход и настройка TOTP в кабинете. До завершения
TOTP привилегированные операции запрещены. Чтобы назначать сотрудников, нужны
площадки данного выпуска; их управление относится к следующему этапу.

HTTPS/proxy, реальные почтовые настройки, управление секретами, восстановление и

миграции. Внешние секреты nsuhw на этом этапе вообще не хранятся.
