# Личный кабинет Сибирской математической олимпиады

Next.js 16 / React 19 / TypeScript / Tailwind 4 / PostgreSQL 17 / Prisma 7 / Better Auth.
Четыре роли: студент, главный организатор, организатор площадки и единственный
технический администратор. Совмещения ролей нет. Администратор действует во всех
годах, назначает/отзывает/заменяет главных и единственный меняет сроки регистрации.
Доступ к спискам участников, экспорту и внешним паролям он не наследует.

## Что работает

Учебная регистрация, подтверждение email кодом, вход/выход, восстановление пароля,
защищённый кабинет и TOTP. Главный организатор назначает/отзывает организаторов
своих площадок после повторной проверки пароля. Год и площадка проверяются сервером.
Существующего студента нельзя повысить этой операцией: совмещения ролей нет.

Ежегодное участие, сроки/ручное закрытие, текущий выпуск, управление площадками
и личная история по годам реализованы в учебном контуре. Команды, объявления,
результаты, дипломы и выдача данных nsuhw ещё не реализованы. Связь сайтов — только переход на nsuhw.ru;
его аккаунт будет сохраняться между годами. Реальные ПДн пока не принимаются.

## Локальный запуск

Нужны Node.js 24, npm, Docker Compose. Команды — в корне checkout:

```sh
npm ci
npm run dev:setup
docker compose up -d --wait
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

`dev:setup` создаёт игнорируемый Git файл `.env` из примера и случайный секрет
Better Auth, сохраняя существующие настройки и непустой секрет. Значение не печатается.
Для учебной регистрации установите `DEMO_REGISTRATION="true"` в `.env` и перезапустите
приложение. Используйте только вымышленные ФИО и email `@example.test`.
В production регистрация закрыта независимо от этого флага.

Скрипт seed повторяем: создаёт только демонстрационный вуз и курс, без пользователей
и реальных согласий. Почта направляется в Mailpit: SMTP 1025, интерфейс 8025.
PostgreSQL — порт 5432. Сервисы Compose привязаны к loopback; реквизиты примера —
только для локальной разработки. Для остановки с сохранением БД: `docker compose stop`.

Необходимы registry.npmjs.org и binaries.prisma.sh. Сетевой блокер Prisma снят;
TLS и проверка checksum сохранены. При восстановлении новой среды запустите Compose
и приложение заново: процессы не являются частью snapshot.

## Проверки

Только отдельная локальная/CI БД с синтетическими данными — никогда production:

```sh
npm run lint
npm run typecheck
npm run test:db
npm run test:http
npm run test:live
npm run build
npm start
```

`test:db`: проверки БД, областей доступа, назначений, сроков, ежегодной записи,
параллельных заявок, истории, списков, фильтров/пагинации и служебных CLI, миграционного перехода и четырёх ролей.
`test:http`: три сквозных сценария через собственный dev-сервер на порту 3100 и
локальный Mailpit, с созданием/очисткой синтетических аккаунтов. Перед ним остановите
другой `next dev` в этом checkout; тесту нужен свободный порт и доступная БД.
HTTP-набор очищает локальные rate-limit fixtures; не запускайте его в общей среде.
`test:live` использует две независимые Chromium-сессии с настоящим входом/TOTP:
проверяет обновление явки за 10 секунд, потерю/восстановление связи и отзыв назначения.
Для локального браузера: `npx playwright install chromium`, затем `npm run test:live`.
В этой облачной машине можно использовать имеющийся Chromium:
`PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:live`.
Наборы запускаются последовательно; не запускайте другой next dev/build/typegen
в этом checkout во время браузерных тестов. CI устанавливает Chromium отдельно.

`GET /api/health`: 200 при доступной БД, 503 при недоступной, без подробностей ошибок.
`GET /api/me`: только текущий подтверждённый пользователь, без токена сессии;
чужая/отозванная сессия получает 401. `/cabinet` перенаправляет гостя на вход.
Для изменения схемы: `npm run db:dev -- --name <name>`; миграцию коммитить.
В CI те же проверки с отдельной PostgreSQL и Mailpit. Локальный успех не является
подтверждением результата удалённого запуска GitHub Actions.

## Учебный технический администратор и главные организаторы

```sh
npm run edition:create -- 2027 "Учебная СМО 2027"
npm run admin:bootstrap -- admin@example.test "Учебный администратор"
```

CLI выполняет оператор с локальным доступом к БД. Она не создаёт пароль, не повышает
существующие роли и не позволяет создать второго администратора. Повтор с тем же
email безопасен и отзывает его сессии. Прежняя staff:bootstrap отключена.
Для администратора: восстановить пароль через сайт (письмо в Mailpit), подтвердить
email, войти и подключить TOTP. Далее раздел «Техническое администрирование» позволяет
назначить главного для выбранного года и задать сроки в Новосибирске (UTC+7).
Каждая операция требует текущий пароль; общий лимит — пять проверок за минуту.

Новый главный также устанавливает пароль через восстановление, подтверждает email
и подключает TOTP. Он управляет площадками и их организаторами, названием и выбором
текущего выпуска в назначенных годах. Сроки и ручное закрытие ему недоступны, в том
числе через прямой API. Переключение текущего требует прав на оба года.

Администратор может отозвать назначение главного на год или заменить всех действующих
главных года выбранным аккаунтом атомарно. Аккаунты, роли и история сохраняются;
назначения других лет не отзываются. Сессии адресатов удаляются. Главный без действующего
назначения не получает доступ к предметным данным. Студенты и организаторы площадок
не повышаются в главных. Все аккаунты пока только синтетические @example.test.

Студент в разделе «Моё участие в олимпиаде» подтверждает ФИО/вуз/курс на каждый год,
выбирает площадку либо дистанционный МСК/НСК. Начало периода включено, момент
окончания исключён; ручное закрытие приоритетнее расписания. При регистрации
текущий профиль обновляется, история хранит самостоятельный снимок. Повторный POST
не меняет уже выбранную площадку. Отключённая площадка исчезает из новых вариантов,
но остаётся в истории прежних участников.

Для нового года повторите edition:create и назначьте главного через администратора; права не переносятся
автоматически. В форме площадки можно выбрать прежнюю постоянную площадку и задать
отдельные сведения нового года, не меняя старый. Данные студентов в истории чужому
аккаунту не возвращаются.

## Списки участников

В кабинете организатора после TOTP доступен раздел «Участники олимпиады». Главный
видит участников назначенных лет, организатор площадки — своих назначенных площадок,
включая отключённые. Дистанционных участников видит главный организатор.

Поддерживаются поиск по ФИО/email, фильтры года/площадки/вуза/курса/статуса/формата,
сортировка и страницы по 10/25/50/100 строк. Вуз и курс соответствуют снимку участия,
а не изменённому позднее профилю. Команда включена в список, фильтр, сортировку и CSV; scope по площадке не расширяется.
Поиск не помещает ФИО/email в URL. Кнопка «Скачать CSV по фильтрам» выгружает все страницы текущего фильтра, с повторной
серверной проверкой года/площадок и TOTP. CSV UTF-8 с BOM, запятая, кавычки и CRLF;
текстовые формулы нейтрализуются апострофом. Файл не сохраняется на сервере, ответ
no-store; в аудит пишется область и количество строк, без поисковых ФИО/email.
Синхронная выгрузка ограничена 10000 строками: при превышении нужно уточнить фильтры,
частичного файла нет. В строке списка можно исправить явку: не отмечено / присутствовал / не присутствовал.
При конфликте ревизий обновите список; чужая площадка запрещена сервером.
Применённый список обновляется каждые 5 секунд. Несохранённые фильтры автоматически
не применяются. Потеря связи скрывает прежние строки, успешный повтор восстанавливает
список. После 401/403 строки скрываются и автоматические запросы прекращаются.

## Профиль и исправления заявки

В кабинете студента есть отдельная кнопка «Редактировать профиль» для ФИО, вуза и курса.
Она доступна и до первой заявки. Текущий профиль не меняет снимки уже поданных заявок.
Email, роль и площадка в редактор не входят.

У поданной заявки есть отдельное исправление сведений: студент — до окончания срока,
если приём не закрыт вручную; главный назначенного года — после окончания или ручного
закрытия, с обязательной причиной и текущим паролем (пять проверок в минуту, TOTP).
В списке главного ссылка называется «Исправить после закрытия». Нельзя исправлять
чужой год, отменённую заявку, менять площадку или подменять пользователя.
Собственная правка обновляет выбранную заявку и текущий профиль; правка главным
меняет только выбранную заявку. Остальные годы сохраняются. Ревизии защищают
параллельные изменения от затирания. Причина хранится отдельно в защищённой записи
исправления, в аудит попадает только её ID/ревизия, без копий ФИО и текста причины.

Отмена участия доступна отдельной ссылкой с подтверждением: студенту до закрытия,
главному после закрытия с причиной/паролем/TOTP. Членство освобождается; если отменён
капитан, команда удаляется целиком, остальные заявки сохраняются. Восстановления
нет, повторный POST регистрации отмену не обходит. История и аккаунт сохраняются.
Перенос с уведомлением ещё не реализован (C11), он будет только между очными площадками.

## Команды (основа D01)

Студент с заявкой открывает «Команды олимпиады» и создаёт команду своего вуза/года
до окончания или ручного закрытия регистрации. Имя — аббревиатура с номером 1–3,
капитан занимает одно из пяти мест, тренер указывается ФИО без отдельного аккаунта.
Состав доступен только участникам команды; в закрытом году — чтение. Приглашения по точному email принимаются в ЛК получателем (письмо не отправляется).
Капитан может отозвать приглашение, исключить участника и предложить капитанство;
передача действует только после подтверждения новым капитаном. Участник может выйти,
капитан сначала передаёт капитанство. Все действия доступны только до закрытия.
Лимит — 20 запросов приглашений в минуту на аккаунт; общего каталога пользователей нет. Пока состоите в команде, менять вуз заявки
нельзя. Текущий профиль отдельно не меняет вуз в снимке заявки.

Конкурентные лимиты команд проверены: четвёртая команда, шестой участник и два
одновременных членства не создаются. Браузерный test:live также сохраняет профиль,
создаёт команду и принимает приглашение второй учётной записью через интерфейс.
