# Личный кабинет Сибирской математической олимпиады

> AUTH04: TOTP/2FA удалены; обычный вход сохранён. Обновление существующей БД
> и результаты проверок — [TOTP_REMOVAL.md](docs/TOTP_REMOVAL.md).

Next.js 16 / React 19 / TypeScript / Tailwind 4 / PostgreSQL 17 / Prisma 7 / Better Auth.
Четыре роли: студент, главный организатор, организатор площадки и единственный
технический администратор. Совмещения ролей нет. Администратор действует во всех
годах, назначает/отзывает/заменяет главных и единственный меняет сроки регистрации.
Доступ к спискам участников, экспорту и внешним паролям он не наследует.

## Что работает

Учебная регистрация, подтверждение email кодом, вход/выход, восстановление пароля,
защищённый кабинет. Главный организатор назначает/отзывает организаторов
своих площадок после повторной проверки пароля. Год и площадка проверяются сервером.
Существующего студента нельзя повысить этой операцией: совмещения ролей нет.

Ежегодное участие, сроки/ручное закрытие, текущий выпуск, управление площадками
и личная история по годам реализованы в учебном контуре. Команды, объявления и рассылки реализованы.
Загрузка и предпросмотр личных результатов E07 реализованы в учебном контуре;
публикация и защищённое чтение E08 также реализованы. Массовая загрузка, отдельная публикация и выдача дипломов реализованы в учебном контуре. Генерация, ручная передача и защищённый показ данных nsuhw доступны в учебном контуре. Связь сайтов — только переход на nsuhw.ru;
его аккаунт будет сохраняться между годами. Реальные ПДн пока не принимаются.

## Локальный запуск

Нужны Node.js 24, npm, Docker Compose. Команды — в корне checkout:

```sh
npm ci
npm run dev:setup
docker compose up -d --wait
npm run db:generate
npm run db:migrate
npm run db:seed
# Перед учебной регистрацией новых аккаунтов nsuhw (после включения DEMO_REGISTRATION):
DEMO_REGISTRATION=true npm run nsuhw:keys -- init
npm run dev
```

`dev:setup` создаёт игнорируемый Git файл `.env` из примера и случайный секрет
Better Auth, сохраняя существующие настройки и непустой секрет. Значение не печатается.
Для учебной регистрации установите `DEMO_REGISTRATION="true"` в `.env` и перезапустите
приложение. Используйте только вымышленные ФИО и email `@example.test`.
В production регистрация закрыта независимо от этого флага.

Скрипт seed повторяем: создаёт только демонстрационный вуз и курс, без пользователей
и реальных согласий. Почта направляется в Mailpit: SMTP 1025, интерфейс 8025.
PostgreSQL — порт 5432. Сервисы Compose привязаны к loopback; реквизиты примера —
только для локальной разработки. Для остановки с сохранением БД: `docker compose stop`.

Необходимы registry.npmjs.org и binaries.prisma.sh. Сетевой блокер Prisma снят;
TLS и проверка checksum сохранены. При восстановлении новой среды запустите Compose
и приложение заново: процессы не являются частью snapshot.

## Проверки

Только отдельная локальная/CI БД с синтетическими данными — никогда production:

```sh
npm run lint
npm run typecheck
npm run test:db
npm run test:files
npm run test:http
npm run test:communications
npm run test:live
npm run build
npm run check:build
npm start
```

`test:db`: проверки БД, областей доступа, назначений, сроков, ежегодной записи,
параллельных заявок, истории, списков, фильтров/пагинации и служебных CLI, миграционного перехода и четырёх ролей.
`test:http`: шесть сквозных сценариев через собственный dev-сервер на порту 3100 и
локальный Mailpit, с созданием/очисткой синтетических аккаунтов. Перед ним остановите
другой `next dev` в этом checkout; тесту нужен свободный порт и доступная БД.
HTTP-набор очищает локальные rate-limit fixtures; не запускайте его в общей среде.
`test:live` использует две независимые Chromium-сессии с настоящим входом по email/паролю:
проверяет обновление явки за 10 секунд, потерю/восстановление связи и отзыв назначения.
Для локального браузера: `npx playwright install chromium`, затем `npm run test:live`.
В этой облачной машине можно использовать имеющийся Chromium:
`PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:live`.
Наборы запускаются последовательно; не запускайте другой next dev/build/typegen
в этом checkout во время браузерных тестов. CI устанавливает Chromium отдельно.

Перед `test:files` и `test:communications` запустите настоящий ClamAV:
`docker compose --profile files up -d --wait clamav`. Для HTTP-наборов требуется
учебный keyring (`DEMO_REGISTRATION=true npm run nsuhw:keys -- init`).
Повторная учебная приёмка после E09/E10, матрица покрытия и открытые условия:
[F02_ACCEPTANCE.md](docs/F02_ACCEPTANCE.md). Успех этих наборов не закрывает
эксплуатационную приёмку и не разрешает реальные ПДн.

`GET /api/health`: 200 при доступной БД, 503 при недоступной, без подробностей ошибок.
`GET /api/me`: только текущий подтверждённый пользователь, без токена сессии;
чужая/отозванная сессия получает 401. `/cabinet` перенаправляет гостя на вход.
Для изменения схемы: `npm run db:dev -- --name <name>`; миграцию коммитить.
В CI те же проверки с отдельной PostgreSQL и Mailpit. Локальный успех не является
подтверждением результата удалённого запуска GitHub Actions.

## Учебный технический администратор и главные организаторы

```sh
npm run edition:create -- 2027 "Учебная СМО 2027"
npm run admin:bootstrap -- admin@example.test "Учебный администратор"
```

CLI выполняет оператор с локальным доступом к БД. Она не создаёт пароль, не повышает
существующие роли и не позволяет создать второго администратора. Повтор с тем же
email безопасен и отзывает его сессии. Прежняя staff:bootstrap отключена.
Для администратора: восстановить пароль через сайт (письмо в Mailpit), подтвердить
email и войти. Далее раздел «Техническое администрирование» позволяет
назначить главного для выбранного года и задать сроки в Новосибирске (UTC+7).
Каждая операция требует текущий пароль; общий лимит — пять проверок за минуту.

Новый главный также устанавливает пароль через восстановление, подтверждает email
и входит по email/паролю. Он управляет площадками и их организаторами, названием и выбором
текущего выпуска в назначенных годах. Сроки и ручное закрытие ему недоступны, в том
числе через прямой API. Переключение текущего требует прав на оба года.

Администратор может отозвать назначение главного на год или заменить всех действующих
главных года выбранным аккаунтом атомарно. Аккаунты, роли и история сохраняются;
назначения других лет не отзываются. Сессии адресатов удаляются. Главный без действующего
назначения не получает доступ к предметным данным. Студенты и организаторы площадок
не повышаются в главных. Все аккаунты пока только синтетические @example.test.

Студент в разделе «Моё участие в олимпиаде» подтверждает ФИО/вуз/курс на каждый год,
выбирает площадку либо дистанционный МСК/НСК. Начало периода включено, момент
окончания исключён; ручное закрытие приоритетнее расписания. При регистрации
текущий профиль обновляется, история хранит самостоятельный снимок. Повторный POST
не меняет уже выбранную площадку. Отключённая площадка исчезает из новых вариантов,
но остаётся в истории прежних участников.

Для нового года повторите edition:create и назначьте главного через администратора; права не переносятся
автоматически. В форме площадки можно выбрать прежнюю постоянную площадку и задать
отдельные сведения нового года, не меняя старый. Данные студентов в истории чужому
аккаунту не возвращаются.

## Списки участников

В кабинете организатора после входа доступен раздел «Участники олимпиады». Главный
видит участников назначенных лет, организатор площадки — своих назначенных площадок,
включая отключённые. Дистанционных участников видит главный организатор.

Поддерживаются поиск по ФИО/email, фильтры года/площадки/вуза/курса/статуса/формата,
сортировка и страницы по 10/25/50/100 строк. Вуз и курс соответствуют снимку участия,
а не изменённому позднее профилю. Команда включена в список, фильтр, сортировку и CSV; scope по площадке не расширяется.
Поиск не помещает ФИО/email в URL. Кнопка «Скачать CSV по фильтрам» выгружает все страницы текущего фильтра, с повторной
серверной проверкой прав на год/площадки. CSV UTF-8 с BOM, запятая, кавычки и CRLF;
текстовые формулы нейтрализуются апострофом. Файл не сохраняется на сервере, ответ
no-store; в аудит пишется область и количество строк, без поисковых ФИО/email.
Синхронная выгрузка ограничена 10000 строками: при превышении нужно уточнить фильтры,
частичного файла нет. В строке списка можно исправить явку: не отмечено / присутствовал / не присутствовал.
При конфликте ревизий обновите список; чужая площадка запрещена сервером.
Применённый список обновляется каждые 5 секунд. Несохранённые фильтры автоматически
не применяются. Потеря связи скрывает прежние строки, успешный повтор восстанавливает
список. После 401/403 строки скрываются и автоматические запросы прекращаются.

## Профиль и исправления заявки

В кабинете студента есть отдельная кнопка «Редактировать профиль» для ФИО, вуза и курса.
Она доступна и до первой заявки. Текущий профиль не меняет снимки уже поданных заявок.
Email, роль и площадка в редактор не входят.

У поданной заявки есть отдельное исправление сведений: студент — до окончания срока,
если приём не закрыт вручную; главный назначенного года — после окончания или ручного
закрытия, с обязательной причиной и текущим паролем (пять проверок в минуту).
В списке главного ссылка называется «Исправить после закрытия». Нельзя исправлять
чужой год, отменённую заявку, менять площадку или подменять пользователя.
Собственная правка обновляет выбранную заявку и текущий профиль; правка главным
меняет только выбранную заявку. Остальные годы сохраняются. Ревизии защищают
параллельные изменения от затирания. Причина хранится отдельно в защищённой записи
исправления, в аудит попадает только её ID/ревизия, без копий ФИО и текста причины.

Отмена участия доступна отдельной ссылкой с подтверждением: студенту до закрытия,
главному после закрытия с причиной/паролем. Членство освобождается; если отменён
капитан, команда удаляется целиком, остальные заявки сохраняются. Восстановления
нет, повторный POST регистрации отмену не обходит. История и аккаунт сохраняются.
Перенос с уведомлением C11 доступен главному только между очными площадками.

## Команды (основа D01)

Студент с заявкой открывает «Команды олимпиады» и создаёт команду своего вуза/года
до окончания или ручного закрытия регистрации. Имя — аббревиатура с номером 1–3,
капитан занимает одно из пяти мест, тренер указывается ФИО без отдельного аккаунта.
Состав доступен только участникам команды; в закрытом году — чтение. Приглашения по точному email принимаются в ЛК получателем (письмо не отправляется).
Капитан может отозвать приглашение, исключить участника и предложить капитанство;
передача действует только после подтверждения новым капитаном. Участник может выйти,
капитан сначала передаёт капитанство. Все действия доступны только до закрытия.
Лимит — 20 запросов приглашений в минуту на аккаунт; общего каталога пользователей нет. Пока состоите в команде, менять вуз заявки
нельзя. Текущий профиль отдельно не меняет вуз в снимке заявки.

Конкурентные лимиты команд проверены: четвёртая команда, шестой участник и два
одновременных членства не создаются. Браузерный test:live также сохраняет профиль,
создаёт команду и принимает приглашение второй учётной записью через интерфейс.

## Очередь писем D05

Задания сохраняются в одной транзакции с предметным изменением; один источник/версия
и адресат не создают дубликатов. Письма получают также отменившие участие. Пароли,
auth-токены и внешние учётные данные в задания не включаются. Шаблоны поддерживают
только {{name}}, {{year}}, {{university}}, {{team}}, {{venue}}; вставленные значения
не интерпретируются как шаблон повторно, письма — обычный текст.

После запуска PostgreSQL/Mailpit worker запускается отдельно в корне checkout:

```sh
DEMO_REGISTRATION=true npm run worker
# До 20 заданий, затем выход; удобно для проверки и повторного запуска:
DEMO_REGISTRATION=true npm run worker -- --once
```

В worker требуется учебный режим и адреса @example.test; без настройки он отказывает
до взятия заданий. Процессы не переживают восстановление среды — worker нужно
запускать заново. Непустой BETTER_AUTH_SECRET не менять. SMTP использует существующие
переменные .env и сохраняет TLS в production; production-рассылки пока запрещены.

Аренда задания — 90 секунд, тайм-ауты SMTP ограничены, неудачная отправка повторяется
с задержкой до пяти попыток. После исчерпания — FAILED с фиксированным кодом ошибки
без текста SMTP/ПДн. Просроченную аренду подхватывает следующий worker; устаревший
результат не перезаписывает новую квитанцию. Отзыв назначения главного останавливает
ещё не отправленные задания; изменение площадки исключает устаревшую адресацию.
Crash после приёма SMTP и до записи результата может дать повторную доставку:
Message-ID стабилен, абсолютная однократность внешнего email не обещается.

При первом входе служебного аккаунта после восстановления пароля форма отправит
код подтверждения email и откроет его ввод. Смена пароля сама по себе не подтверждает
адрес. После подтверждения войдите с новым паролем.

## Объявления D04

В кабинете главного: «Объявления», год, аудитория всего года либо площадки,
текст и важность. Черновик можно редактировать; публикация требует отдельное
подтверждение и текущий пароль. Опубликованный текст неизменяем, исправление
публикуйте новым объявлением. Студент видит только адресованные публикации,
включая после отмены участия. Для важных писем запустите worker по инструкции D05.

`npm run test:communications` проверяет публикацию/чтение в Chromium и прямые API
в отдельной временной локальной БД; нужен Chromium и CREATE DATABASE. БД после
теста удаляется целиком. Для npm при недоступном домашнем кеше используйте
`npm ci --cache /workspace/.npm-cache`.

## Рассылки D06

Главный открывает «Рассылки», выбирает год/площадку, тему и текст. Доступны
{{name}}, {{year}}, {{university}}, {{team}}, {{venue}}. Пароли/токены в письмах
запрещены. Отправка требует подтверждения и пароля; доставка — worker D05.
Повтор выбирается из истории и требует отдельной отметки: аудитория вычисляется
заново для исходного года/площадки, включая отменившихся участников. Изменённый
шаблон отправляйте новой рассылкой, с новым подтверждением.

## Перенос площадки C11

У главного организатора в списке действующих очных участников есть «Перенести
на площадку». Выберите другую активную площадку того же года, укажите причину,
текущий пароль и подтвердите. Формат/дистанционная зона не меняются,
команда и явка сохраняются. При конфликте обновите страницу; уведомление участнику
доставляет worker D05. Отменённые/дистанционные заявки переносить нельзя.

HTTP/браузерные наборы запускайте последовательно. Runner использует отдельный
генерируемый каталог `.next/test-runtime`, очищает только его до/после запуска и
ждёт завершения своего dev-сервера. Обычные dev/build используют `.next`.
Постоянные test-runtime пути включены в tsconfig; случайные пути не добавляются.
Это устраняет наблюдавшиеся циклы HMR при смешивании dev/production-артефактов.

## Старый аккаунт nsuhw (E00)

Если аккаунт nsuhw уже был, укажите его логин при учебной регистрации с отдельной
отметкой либо в кабинете «Старый аккаунт nsuhw». Пароль внешнего сайта не вводите.
Поданная заявка ещё не подтверждает связь. После регистрации на год главный
организатор увидит её, сверит с ответственным за nsuhw вне сайта и подтвердит
с текущим паролем. Состояние можно обновить в том же разделе кабинета.

Учтены только вымышленные данные. Генерация/выдача новых паролей подключены отдельно в E04–E06; само создание на
nsuhw выполняет главный вручную через таблицу. Исправление/отклонение/перепривязка ошибочной заявки
через сайт также ещё не реализованы; такие случаи разбираются с главным отдельно.

## Имя и фамилия для будущего логина nsuhw (E04a)

При новой регистрации ФИО вводится в исходном написании. Отдельно укажите имя
и фамилию латинскими буквами A–Z для логина (без пробелов и знаков). Будет показан
предварительный smc.i.petrov; это не зарезервированный/выданный логин. Уникальный логин и отдельный пароль
теперь готовятся в E04; предпросмотр до подготовки не резервирует имя. При наличии старого nsuhw выберите
соответствующую отметку и подайте старый логин вместо латинских полей.

Уже зарегистрированный студент без декларации старого аккаунта может открыть
«Аккаунт nsuhw», проверить свою заявку и загрузить редактор данных для нового
логина. Сохранение этих полей не меняет ФИО, профиль и поданные заявки.

## Учебные ключи внешних паролей (E01)

После db:migrate, в корне checkout (только синтетические данные):

```sh
DEMO_REGISTRATION=true npm run nsuhw:keys -- init
# Повтор сохраняет существующие ключи. Значения не печатаются.
```

Ключи находятся в игнорируемом .local/nsuhw-keyring.json (0600), отдельно от БД
и BETTER_AUTH_SECRET. Путь можно задать NSUHW_KEYRING_FILE. Не удаляйте файл и
не коммитьте его. При потере ключей нужны их защищённые резервные копии: init
отказывается заменять потерянный keyring при наличии шифрованных данных в БД.
Копии ключей храните отдельно от копий БД. Production этим backend не поддерживается.

Для учебной ротации остановите приложение/worker, сохраните резервную копию ключей:

```sh
DEMO_REGISTRATION=true npm run nsuhw:keys -- add-version v2
DEMO_REGISTRATION=true npm run nsuhw:keys -- rewrap
```

Старые ключи остаются в файле. Повтор rewrap безопасен; внешний пароль не меняется.
При ошибке часть записей могла уже обновиться — восстановите доступ к старым ключам
и повторите. Не удаляйте старые ключи: автоматической процедуры их удаления нет.
Подготовленная запись не означает создание аккаунта на nsuhw. Генератор/выдача
паролей подключены отдельными задачами E04–E06 с проверками доступа.

## Подготовка новых данных nsuhw (E04)

Перед учебной регистрацией выполните nsuhw:keys init по инструкции E01. Signup
с латинскими именем/фамилией атомарно готовит уникальный в ЛК логин и шифрованный
отдельный пароль. Старые локальные пользователи без legacy-заявки могут сохранить
латинские данные и нажать «Подготовить данные nsuhw». Повтор не меняет пароль.
При stale-предпросмотре обновите форму; выданное имя не переименовывается профилем.

Статус «подготовлен» относится к нашему ЛК. Аккаунт на nsuhw создаёт главный
вручную через таблицу; передача доступна в E05, отдельный показ владельцу — в E06.
До подтверждения успешной загрузки участнику пароль не показывается. Неизвестные
старые логины могут потребовать отдельной сверки на внешнем сайте.

## Передача в nsuhw (E05, учебный контур)

Главный организатор открывает «Передача аккаунтов в nsuhw», выбирает год и обновляет
предпросмотр. Новый CSV содержит только действующих участников с новыми ещё не
подтверждёнными аккаунтами: Логин, пароль, ФИО из заявки. Нужны текущий пароль и
подтверждение состава. Формат UTF-8 BOM, запятая, кавычки, CRLF. Для скачивания
нужен HTTPS либо localhost учебной среды. Реальный импорт nsuhw ещё не проверен.

Загрузите файл на nsuhw через защищённое соединение, не перезаписывая старые
аккаунты. При конфликте/частичном успехе не подтверждайте весь файл. После проверки
успеха всех строк удалите временный файл с компьютера и подтвердите именно эту
выгрузку в ЛК (текущий пароль). Только тогда фиксируется создание и отправляется
уведомление без секрета. Не отправляйте CSV обычной почтой/по общей ссылке.
На сервере файл не хранится. Повтор подтверждения не меняет пароль и не дублирует
письма. Готовые/старые логины участников года видны отдельно для повторного использования.

## Показ пароля nsuhw (E06)

Участник открывает «Аккаунт nsuhw», проверяет свою заявку и готовность нового
аккаунта. После подтверждения создания главным доступен показ собственного
пароля с новым вводом текущего пароля ЛК и явной отметкой. Повторный просмотр
разрешён; внешний пароль не меняется. Не более пяти попыток в минуту.

Пароль скрывается по кнопке, через минуту и при уходе/потере фокуса вкладки.
В URL или хранилище браузера он не сохраняется; восстановление пароля ЛК не
меняет пароль nsuhw. ЛК не знает старый пароль legacy-аккаунта: используйте
известный вам пароль или восстановление непосредственно на nsuhw.

## Загрузка личных результатов (E07)

Главный назначенного года открывает «Загрузка личных результатов».
Выберите год, предварительный/итоговый вид и синтетический UTF-8 CSV до 512 КиБ:
`Логин,Задача 1,…,Задача N,Сумма,Приз`. Логин nsuhw должен быть подтверждён.
Нажмите «Предпросмотр результатов», проверьте строки и ошибки; затем подтвердите
загрузку только верных строк с текущим паролем. Ошибочные строки пропускаются.
Повтор после сетевой ошибки безопасен; при изменении данных нужен новый просмотр.

Ноль и отсутствие оценки различаются, сумма не вычисляется автоматически.
Существующие результаты не заменяются, все дубли участника в файле отклоняются.
Загрузка не публикует данные и не отправляет письма. Студент получает результаты после отдельной публикации E08 в разделе «Результаты». Командный импорт отложен; общий рейтинг
на стороннем сайте не связан с нашим проектом. Контракт, коды ошибок и ограничения:
[E07_RESULT_IMPORT.md](docs/E07_RESULT_IMPORT.md).

`npm run check:build` после сборки проверяет, что server traces не включают
.local/ и .env*. Ключи и env передаются средой отдельно от артефакта; нестандартный
NSUHW_KEYRING_FILE также должен находиться вне упаковки проекта. Учебный локальный
backend в production по-прежнему запрещён. Build может сообщать о широком tracing
из существующего динамического доступа к keyring: успешный checker подтверждает
исключение локальных секретов, но не production-готовность.

В разделе загрузки результатов главный может открыть «Проверка сохранённых загрузок»:
выбрать год, загрузку и просмотреть сохранённые строки по 25. Это позволяет проверить
баллы/сумму/приз после перезагрузки страницы. Раздел доступен только главному
назначенного года; он не публикует результаты и не открывает их студенту.

## Публикация результатов E08

После проверки сохранённой загрузки главный вводит пароль и подтверждает публикацию
всего выбранного batch. Уведомления доставляет worker; письмо не содержит баллы.
Каждая загрузка публикуется отдельно. В разделе «Результаты» студент видит только
свои опубликованные данные; после своих итоговых предварительные скрываются.
Главный видит опубликованные версии назначенного года, организатор — своей площадки.
Импорт сам по себе не публикует данные. Публикация неизменяема, исправление/отзыв
не реализованы. Только учебные данные; общий сайт результатов не интегрируется.

Внутренний учебный карантин E09a используется контуром дипломов вместе с ZIP/PDF/AV
проверками; сам примитив хранения не является антивирусом. Границы и открытые
вопросы: [E09_PRIVATE_FILES.md](docs/E09_PRIVATE_FILES.md).

Массовый ZIP дипломов согласован: PDF в корне с именами по логинам nsuhw,
10 МиБ/PDF, 50 МиБ/ZIP, до 1000 файлов. Проверка ZIP, загрузка, сканирование и выдача подключены в E09/E10 ниже. Подробности —
E09_PRIVATE_FILES.md; не загружайте реальные дипломы в учебную среду.

Для учебной проверки настоящего антивируса (нужны Docker и около 2 GiB RAM):

```sh
docker compose --profile files up -d --wait clamav
npm run test:files
# Когда не нужен:
docker compose --profile files stop clamav
```

Тест использует доброкачественные байты и стандартный EICAR, без реальных файлов.
Сканер подключён к проверке PDF при подготовке пакетов. Образ/базы закреплены; обновление баз и
production-приёмка не проверены. Подробные ограничения — E09_PRIVATE_FILES.md.

Проверка PDF теперь включает настоящий разбор структуры/активного содержимого в
изолированном процессе и реальный ClamAV. Для test:files нужен Linux с
/usr/bin/prlimit (util-linux) и запущенный files-профиль. Отсутствие инструмента
даёт отказ, без ослабленного режима. Полный UI дипломов описан в следующем разделе.

## Массовые дипломы E09/E10

Актуальное продолжение подготовительных E09a–d: загрузка/выдача через UI реализованы.
Перед работой включите учебный `DEMO_REGISTRATION=true` в .env, перезапустите приложение
и запустите `docker compose --profile files up -d --wait clamav`.
Главный организатор открывает «Дипломы», выбирает год, ZIP и подтверждает проверку с
паролем. Имена PDF в корне ZIP — точные логины nsuhw. Дождитесь предпросмотра,
проверьте участников/ошибки и выберите новый документ либо замену. Старый PDF можно
скачать перед заменой. Подтвердите назначения с паролем, затем отдельно опубликуйте
пакет с новым подтверждением. Отправку уведомлений выполняет обычный mail worker.

Студент открывает «Дипломы» → «Показать мои дипломы» и скачивает свои опубликованные
PDF. До публикации замены прежний доступен, после — только новый. Несколько дипломов
одному участнику загружайте разными пакетами. Подготовка не фоновая: крупные ZIP могут
занять несколько минут или потребовать разделения. Полный контракт и ограничения —
[E09_PRIVATE_FILES.md](docs/E09_PRIVATE_FILES.md). Реальные дипломы не загружать.

`test:files` теперь проверяет и предметный DB-сценарий дипломов: нужны PostgreSQL,
миграции/генерация Prisma и настоящий локальный ClamAV. `DIPLOMA_DIRECTORY` по
умолчанию .local/diplomas; каталог приватный и исключён из Git/артефакта. Не используйте
public/.next/out. Нестандартный каталог должен быть вне упаковки приложения;
check:build также проверяет его, если переменная настроена. Ключи БД, права, сроки,
очистка orphan и production-приёмка остаются обязательными перед реальным запуском.

## Импорт готовых аккаунтов nsuhw — E02/E03

Главный назначенного года после входа открывает «Импорт готовых аккаунтов nsuhw».
Загрузите синтетический UTF-8 CSV до 512 КиБ/1000 строк с заголовками
`ID пользователя ЛК,логин nsuhw,пароль nsuhw`. UUID должен принадлежать
подтверждённому студенту с участием этого года. Нужен уже действующий аккаунт,
проверенный у ответственного за nsuhw: импорт не создаёт его на внешнем сайте.

Проверьте отчёт без паролей, введите текущий пароль ЛК и подтвердите применение
верных строк. Дубли отклоняются все, существующие аккаунты/legacy-заявки не заменяются.
После успеха владелец получает уведомление и может посмотреть пароль через E06.
Исходник сервер не сохраняет; скачанные/исходные файлы удалите со своего компьютера.
Контракт и проверки — [E02_ACCOUNT_IMPORT.md](docs/E02_ACCOUNT_IMPORT.md).

## Копии, восстановление и нагрузка

Учебные команды: `backup:create -- --confirmed-quiesced`, `backup:retention`
(план), `backup:retention -- --apply`, `backup:restore -- <UUID> --confirmed-isolated`.
Запускайте через `DEMO_REGISTRATION=true npm run <команда>`, с остановленными app/worker.
Ключ копий `.local/backup-key` хранится отдельно от `.local/backups`; не теряйте его.
Восстановление создаёт новую БД и runtime.env в приватном каталоге, не меняет
рабочую БД или корневую .env и не публикует приложение.

`npm run test:ops` выполняет настоящий локальный PostgreSQL/files/keys restore-drill,
нужны Compose PostgreSQL/ClamAV. В CI PostgreSQL-контейнер выбирается через PG_CONTAINER.
`npm run test:load` автоматически строит изолированный production-артефакт, проверяет
traces и запускает его на loopback с отдельной временной БД: 5000 участников в каждом из двух
годов и 200 активных HTTP-сессий. Запускать последовательно с остальными HTTP-наборами.
Инструкции, результаты и ограничения — [OPERATIONS.md](docs/OPERATIONS.md).
Production запрещён до закрытия указанного там списка условий запуска.

Итог согласованного учебного релиза: [RELEASE_HANDOFF.md](docs/RELEASE_HANDOFF.md).
Все production-условия и запрет реальных ПДн сохраняются.

`DATABASE_POOL_MAX` ограничивает соединения одного app-процесса (по умолчанию 20,
1–50). После изменения нужен перезапуск; сумма app/worker/CLI/инстансов должна
укладываться в лимит PostgreSQL с резервом для обслуживания. Это не автоматическая
production-настройка. Тайм-аут фонового списка остаётся 4 секунды.

## Ручная проверка всех ролей

Пошагово: [MANUAL_TESTING.md](docs/MANUAL_TESTING.md). Используйте разные email
для администратора/главного/организатора площадки/студентов и отдельные профили
браузера либо явный выход. Главного назначает администратор, организатора
площадки — главный; оба устанавливают пароль, подтверждают email и входят по email/паролю.
Не запускайте общие test:db/test:http на БД ручной проверки.

`npm run test:account-switch` сам создаёт временную БД и проверяет UI смены аккаунтов,
регистрацию/письмо/OTP и автозаполнение. Нужен Chromium и свободный порт 3100.
Для диагностики своего синтетического студента: `DEMO_REGISTRATION=true npm run
auth:inspect -- student@example.test`. Вывод — только флаги состояния, без секретов
и изменения данных. Детали — [AUTH_ACCOUNT_SWITCH.md](docs/AUTH_ACCOUNT_SWITCH.md).
