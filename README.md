# Личный кабинет Сибирской математической олимпиады

Учебный сайт с тремя предметными ролями: студент, главный организатор и организатор
площадки; отдельный технический администратор назначает главных и задаёт сроки.
Одна роль на аккаунт, назначения организаторов ограничены годом/площадками.
Разрешены только вымышленные данные и адреса @example.test. Production не разрешён.

Реализованы ежегодное участие, команды, списки/CSV/явка, объявления/письма,
работа с аккаунтами nsuhw (старый логин вводит сам участник без модерации), импорт личных/командных результатов с курсами, версии/отзыв и отдельная публикация,
приватные дипломы с версиями, история и обращения. Это учебная реализация;
[статус и ограничения](docs/STATUS.md) отделяют её от приёмки реальной эксплуатации.

## Локальный запуск

Linux, Node.js 24, npm, Docker Compose. Версии зависимостей — package.json/lockfile.
Стек: Next.js 16, React 19, TypeScript, Tailwind 4, PostgreSQL 17, Prisma 7, Better Auth.
Для Windows используйте [WSL/Ubuntu](docs/WINDOWS_WSL.md).

```sh
npm ci
npm run dev:setup
```

В созданной .env включите DEMO_REGISTRATION="true" и проверьте
BETTER_AUTH_URL="http://localhost:3000". dev:setup сохраняет существующие настройки
и непустой BETTER_AUTH_SECRET. Не заменяйте секрет или ключи существующей БД.

```sh
docker compose up -d --wait
npm run db:generate
npm run db:migrate
npm run db:seed
DEMO_REGISTRATION=true npm run nsuhw:keys -- init
npm run dev
```

Сайт: http://localhost:3000; почта Mailpit: http://localhost:8025.
PostgreSQL/SMTP: 5432/1025; порты Compose привязаны к loopback.
Seed создаёт демонстрационные вуз/курс, без пользователей; повтор безопасен.
Регистрация аккаунта не является ежегодной заявкой: участие подаётся после входа.
В production новая регистрация закрыта независимо от учебного флага.
Для дипломов нужны изолированный PDF-worker (prlimit внутри контейнера):

```sh
docker compose --profile files up -d --build --wait
```

Сетевые зависимости установки: registry.npmjs.org и binaries.prisma.sh;
Docker должен иметь доступ к используемым registry. TLS/checksum не отключать.
Процессы после восстановления среды запускать заново. Для остановки с сохранением
данных: docker compose stop. Не использовать down -v или migrate reset.

## Первый выпуск и служебные аккаунты

```sh
npm run admin:bootstrap -- admin@example.test "Учебный администратор"
```

Команды выполняет локальный оператор. Bootstrap создаёт единственного администратора
без пароля; повтор того же email сохраняет аккаунт и отзывает сессии. Для первого входа
установите пароль через «Забыли пароль?» (письмо Mailpit), подтвердите email, войдите.
На /cabinet/admin создайте выпуск: год, название, текущий пароль и подтверждение.
Затем задайте сроки в Новосибирске (UTC+7) и назначьте главного на год.
CLI edition:create остаётся дополнительным операторским инструментом.

Главный устанавливает пароль через восстановление и подтверждает email; само его
назначение не отправляет приглашение. Он выбирает текущий выпуск, создаёт площадки
и назначает их организаторов. При назначении организатора площадки API запрашивает
письмо установки пароля. Существующего студента эти операции не повышают.
Старый staff:bootstrap отключён. Для нового года нужны новые назначения.

Полный сценарий: [MANUAL_TESTING](docs/MANUAL_TESTING.md).

## Письма и ключи

Worker запускается отдельно с той же .env:

```sh
npm run worker
# Один цикл до 20 заданий:
npm run worker -- --once
```

Нужен учебный флаг; в production worker отказывает. Письма обрабатываются через
outbox, а их постановка в очередь не доказывает доставку. [Контракт писем](docs/contracts/COMMUNICATIONS.md).

Keyring nsuhw по умолчанию: .local/nsuhw-keyring.json (0600). Init сохраняет
существующий валидный файл; потерянный ключ при шифрованных записях не заменяет.
[Выдача/импорт/экспорт nsuhw](docs/contracts/NSUHW.md),
[ротация и восстановление](docs/OPERATIONS.md).

## Проверки

Используйте отдельную синтетическую БД. Общие test:db/test:http не запускать
поверх ручных аккаунтов. Все наборы и их prerequisites — [TESTING](docs/TESTING.md).
Проверки выполняются последовательно; не совмещать их с другим dev/build/typegen.

```sh
npm run lint
npm run typecheck
npm run build
npm run check:build
```

Полный pipeline — [.github/workflows/ci.yml](.github/workflows/ci.yml).
Успех старой ревизии не подтверждает текущий HEAD. npm start запускает собранное
приложение; production guards при этом сохраняются.

GET /api/health возвращает 200 при доступной БД, иначе 503 без подробностей.
GET /api/me выдаёт только текущего подтверждённого пользователя без токена сессии.
Для новой миграции: npm run db:dev -- --name <name>; SQL-миграцию коммитить.
