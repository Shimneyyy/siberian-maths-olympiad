# Работа с репозиторием

## Начало задачи

1. Проверить ветку, HEAD и пользовательские изменения; не подменять их без основания.
2. Прочитать [текущий статус](docs/STATUS.md) и [открытые задачи](docs/TASKS.md).
3. Для затрагиваемой функции читать её контракт из [карты документации](docs/DECISIONS.md),
   соответствующий ADR и код. Архив не является действующей инструкцией.
4. Команды запуска — [README](README.md), проверки — [TESTING](docs/TESTING.md).

## Источники требований

[PRD](docs/PRD.md) сохраняет исходное ТЗ. Поздние принятые уточнения —
[решения](docs/DECISIONS.md); действующее поведение — контракты со ссылками на код.
Реализация не доказывает согласование нового бизнес-правила. При расхождении записать
его в TASKS, указать источник и не расширять права по умолчанию. Не переписывать
исходные требования ради соответствия реализации.

## Границы

Только синтетические данные и email @example.test. Реальные ПДн, production,
публикация среды и merge в main не разрешены. Четыре роли: три предметные и отдельный
единственный TECHNICAL_ADMIN; одна роль на аккаунт. Администратор не наследует
чтение участников, результатов, дипломов и внешних секретов.
Не помещать ПДн, пароли, токены, ключи и исходные выгрузки в Git, логи и отчёты.
Не удалять .env/.local/БД и не выполнять migrate reset ради настройки или тестов.

## Обязательные технические инварианты

- actorId получать из серверной сессии; проверять роль, актуальное назначение,
  год, площадку и владельца на сервере, включая worker и скачивания.
- Общий registrationsScope применяется до строк, COUNT, фасетов и экспорта.
  Отключённые площадки остаются в области старых регистраций.
- Не удалять CHECK, составные FK, частичные индексы и immutable-триггеры SQL-миграций:
  Prisma-схема выражает не все ограничения. Не отключать их для очистки тестов.
- Сохранять ревизии, идемпотентные UUID и повторную проверку под блокировками.
  Год блокируется перед участием; User — перед namespace nsuhw.
- Профиль не переписывает снимки прошлых участий. Повтор регистрации не меняет
  площадку и не восстанавливает отмену. Подробности — [контракт](docs/contracts/PARTICIPATION.md).
- Импорт не является публикацией; подготовленный аккаунт не является подтверждённым
  внешним аккаунтом. Не подменять реальный nsuhw тестовой отметкой успеха.
- Предметная запись, аудит и предусмотренный outbox атомарны. В аудит не копировать
  ФИО, причины исправлений, содержимое CSV/PDF, баллы и секреты.
- Не раскрывать пароль или PDF, если обязательный аудит не сохранён. Ключи и файлы
  не включать в build traces; после build выполнять npm run check:build.
- App/CLI/seed/tests импортируют PrismaPg из src/lib/pg-adapter.ts. При изменении
  адаптера проверять test:pg, rollback, независимость соединений и нагрузку.
- Email и латинские поля auth-форм брать из FormData: autofill может не вызвать
  onChange. Не переносить email/секреты через URL или browser storage.
- Сохранять отдельные ключи внешних паролей и BETTER_AUTH_SECRET; смена секрета
  затрагивает аутентификацию и HMAC импорта. Потерянный ключ не заменять новым.

## Проверки и документация

DB/HTTP/browser/ops/load-наборы запускать последовательно. Общие test:db/test:http
не запускать поверх ручных аккаунтов. Не запускать dev/build/typegen одновременно
с browser runner одного checkout. Писать только фактически выполненные проверки,
с ревизией и ограничениями; старый успех не является проверкой нового кода.

При изменении поведения обновить один соответствующий контракт. Новое решение
оформить ADR, открытый вопрос — в TASKS, актуальную границу проверки — в STATUS.
Не копировать один отчёт в несколько документов. Не добавлять журналы сессий в AGENTS.
