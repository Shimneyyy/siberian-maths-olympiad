## AUDIT02 — предупреждение pg о конкурентном client.query

Пользователь отдельно сообщил Console Error на странице Registrations. В первом
пакете оно **не исправлялось** и было явно оставлено в отчёте. Воспроизведение
`node --trace-deprecation --import tsx --test tests/registrations.test.ts` показало
цепочку pg.Client.query → Prisma PgTransaction.queryRaw → relation loader Prisma.
Последовательные await в listRegistrations не исключают параллельных SQL-запросов
внутри одной ORM-операции с вложенными select.

Исправление — общая фабрика `src/lib/pg-adapter.ts`. На каждой транзакции она
последовательно исполняет queryRaw/executeRaw, а commit/rollback дожидаются ранее
поданных запросов перед возвратом соединения в пул. Ошибка сохраняется для вызывающего
кода и не блокирует последующий rollback. Очереди разных транзакций независимы;
глобальной очереди приложения нет. Публичные интерфейсы адаптера используются без
патча node_modules, без фильтрации предупреждений, downgrade pg или изменения
серверных прав/SQL/DTO/пула/тайм-аутов. App, CLI, seed и тесты используют одну фабрику.

Новый регрессионный сценарий с восемью параллельными adapter-запросами воспроизводит
предупреждение и падает на исходной фабрике, проходит на исправленной. Два других
проверяют rollback после SQL-ошибки и одновременный прогресс независимых транзакций.
В browser live добавлен контроль именно этого console warning при открытии двух
списков участников.

## AUDIT03 — регистрация студента, 503 и Windows

Пользователь сообщил 503 при заполненной форме /register и exists=false из
readonly auth:inspect. Сервер аккаунт не сохранил; ошибка SMTP после commit в таком
случае не объясняет отсутствие записи. CLI keys init также отказала. Пользователь
уточнил нативный Windows PowerShell/CMD и выбрал дальнейший запуск через WSL/Ubuntu.

Найдена несовместимость: demo keyring требует POSIX 0600; Node.js в нативном Windows
не обеспечивает эту проверку через stat.mode. Существующий файл может отклоняться,
а прежний init мог создать файл, который затем сам не мог загрузить. Принят явный
fail-closed отказ Windows до создания/изменения ключа и понятная инструкция CLI.
Проверка прав не отключена; поддержка Windows ACL не заявляется. Для запуска
подготовлена [WINDOWS_WSL.md](WINDOWS_WSL.md): Linux filesystem, сохранение .env/
.local/секрета, прежний Docker Desktop PostgreSQL-том, без reset и без замены ключей.
Точные метаданные пользовательского файла недоступны; конкретное состояние WSL
и успешность регистрации после переноса ещё должны быть проверены пользователем.

Исправлена подтверждённая ошибка формы: любой !response.ok, включая 503, раньше
показывал «Проверьте поля». Теперь фиксированные публичные сообщения различают
ошибку полей, 403, 429, oversized body, общий 5xx, подготовку nsuhw, неподдерживаемую
платформу и ошибку письма после сохранения. Произвольные тексты библиотеки/исключения,
пути, SMTP-ответы и секреты в UI не отражаются. При keyring-сбое транзакция откатывается;
при SMTP-сбое после commit возвращается VERIFICATION_DELIVERY_FAILED и объясняется
повторный запрос OTP без повторной регистрации. Сессия автоматически не выдаётся.

Также воспроизведён DOM-autofill латинского имени: до исправления видимое значение
Autofilled уходило как прежнее Synthetic. Signup теперь читает оба латинских поля
из FormData, аналогично email/паролю. Это самостоятельный дефект формы, не доказанная
причина пользовательского 503.

Новые test:registration/CI проверяют реальную отсутствующую конфигурацию keyring и
реальный отказ SMTP на loopback в отдельных временных БД через Chromium. Проверяются
503/no-store, сообщения UI, rollback либо сохранение полного аккаунта, отсутствие
сессии, секретов/путей в сообщениях и запрет автоматической переинициализации ключа.
Windows guard проверяется в изолированном процессе с подменой platform; настоящего
Windows executor здесь нет. Отказ проверен до создания отсутствующего файла и без
