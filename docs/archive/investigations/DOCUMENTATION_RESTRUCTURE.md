## Результат

Вместо накопительных журналов введены короткий STATUS, реестр решений, семь ADR,
контракты участия/команд, писем, nsuhw, результатов и дипломов. Открытые дефекты и
несогласованные возможности собраны в TASKS с явными статусами. README/AGENTS,
архитектура/безопасность и эксплуатация описывают текущий учебный контур.

Исходное ТЗ сохранено: добавлена только шапка о статусе и ссылках на уточнения.
Практические WSL-инструкции сохранены. Ручная проверка связана с общей картой
автоматических наборов. Исторические отчёты сокращены до границ доказательств со
ссылками на неизменяемые оригиналы в Git; повторные отчёты не копируются в ADR.

Первоначально было 23 Markdown-файла и 7793 строки. Количество новых небольших
файлов больше из-за разделения контрактов и ADR; общий объём существенно меньше.
Цель — читать только правила и контракт задачи, сохраняя доступ к исходной истории.

## Существенные уточнения по коду

- Три предметные роли и отдельный TECHNICAL_ADMIN, без наследования предметных прав.
- Только администратор меняет сроки; организаторов площадок назначает главный.
- Вуз/курс: seed есть, UI/API ведения главным нет; Q11 остаётся расхождением.
- Расширенный JSON-лимит — четыре import endpoint, не два. Multipart отдельно.
- Reauth buckets admin/staff/chief/own-secret различаются; staff service не требует
  пароль самостоятельно. Этот SEC03 сохранён как открытый.
- App DATABASE_POOL_MAX не применяется автоматически к CLI/worker.
- ZIP: общая ошибка структуры/лимита прерывает архив; часть неподдерживаемых записей
  отклоняется пофайлово. PDF/AV и публикация остаются отдельными проверками.
- Импорт не означает публикацию, prepared не означает создание на nsuhw, тестовая
  отметка внешнего успеха не означает реальную интеграцию.
- Checker build проверяет пути traces, а не сканирует содержимое всех артефактов.
- Статус готового задания outbox — READY, а не PENDING.
- Workflow содержит проверяемые наборы, но не отдельный npm audit.
- Исторический успех CI/число тестов не выдаются за проверку текущей ревизии.

## Верификация документационной задачи

Выполнены статическая сверка соответствующих исходников/схем/SQL/скриптов/CI,
проверки локальных Markdown-ссылок, существования исторических источников и якорей
строк в Git, npm-команд и структуры документации. Проверены отсутствие устаревших
инструкций, целостность fenced blocks, сохранение тела PRD, git diff --check и
побайтовая неизменность 252 отслеживаемых файлов вне Markdown относительно базы.

Отдельно проверены по исходникам четыре enlarged import route, 27 SQL-миграций,
Node 24, JSON 16 КиБ, CSV 512 КиБ, ZIP/PDF-лимиты, область app-пула и очередь адаптера.
Это статические проверки контрактов, а не новый запуск приложения или тестов БД.

Зависимости/сервисы/миграции не запускались и не менялись. Runtime, нагрузка,
реальный nsuhw и новый удалённый CI этой задачей не проверены. Production, реальные
ПДн, публикация среды и main не затронуты. Сведения о прошлых запусках явно находятся
в архиве и имеют указанные исходные ревизии.
