## Дефект и исправление

Apply форм результатов/аккаунтов сохранял предпросмотр после отказа доступа либо
конфликта. Теперь status ошибки сохраняется даже для не-JSON ответа: 401/403 очищают
preview, исходник и file input; 409 требует нового preview, сохраняя исходник.
Правило действует также при отказе preview. Сетевую ошибку нельзя считать откатом:
CSV/UUID/hash сохраняются для повтора, пароль/подтверждение вводятся заново.
Полный контракт — [SECURITY](../../SECURITY.md#сбои-форм-импорта).

## Проверки

- lint и typecheck — успешно.
- test:communications — 1/1 расширенный сквозной Chromium/HTTP/SMTP сценарий;
  обе CSV-формы проверены на отказ preview, apply 401/403/409 и повтор после потери ответа.
- build — успешно; сохраняются три прежних предупреждения Turbopack о dynamic filesystem tracing.
- check:build — 75 server traces, local secrets excluded; это проверка путей, не универсальный сканер секретов.
- Документация: 39 Markdown-файлов, 269 относительных ссылок, 68 ссылок на npm scripts;
  несуществующих путей/команд и незакрытых code fences не найдено.


Browser-сценарий вызывает настоящие preview/apply в отдельной временной БД.
Подменяются только HTTP-отказы 401/403/409 и потеря ответа: первый apply выполняется
на сервере и возвращает 200, затем ответ блокируется в браузере. Повтор формы
отправляет тот же UUID/hash. Итоги существующего сценария проверяют одну запись
результата/аккаунта и отсутствие повторных уведомлений. Пароли не печатаются.
