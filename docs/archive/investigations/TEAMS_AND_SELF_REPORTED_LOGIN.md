## Причины и исправления

Удаления команды отдельно от отмены участия не было. Invite query выбирал только
teamMembership=null, поэтому капитан другой команды не получал приглашение.
Добавлены operation=delete с явным подтверждением/правами капитана и приглашения
людям в других командах того же вуза/года. Вступление только после освобождения
прежнего членства; входящие приглашения сохраняются. Годовая блокировка сериализует
удаление/принятие, аудит в транзакции. Другие участники не отменяют свои заявки.

Старый логин раньше требовал проверки главным. По новому запросу это полностью
убрано из функционала: интерфейс/approve/review API, сервисы и поля approved* удалены.
Самоввод owner-only, без внешней проверки, с обычной валидацией поля. Сохранённые
старые логины сразу работают для results/diplomas и списка повторных участников
экспорта. Несколько одинаковых логинов не приводят к произвольному выбору владельца:
неоднозначный импорт отклоняется. Генерация новых аккаунтов и подтверждение их
реального создания не меняются.

Согласован новый CSV: ФИО,Курс,Вуз,Логин,Задача 1,…,Сумма баллов, необязательный Приз.
Старый формат работает. Логин/год задают соответствие; metadata из файла показаны
в предпросмотре, без изменения профиля/снимка. Сумма не пересчитывается. После
отдельной публикации достижение доступно только своему студенту и в личной истории.

## Обновление существующей учебной среды

Остановить app/worker, сохранить согласованную копию БД/файлов/ключей и прежнюю .env.
После получения изменений work1:

```sh
npm ci
npm run db:generate
npm run db:migrate
```

Миграция 20261120090000_self_reported_nsuhw_login сохраняет id/userId/login/revision/
createdAt всех строк, включая дубли и прежние ожидавшие проверки. Удаляет только
метаданные/индекс/ограничения модерации и добавляет обычный индекс login. Всего
28 миграций. Reset БД, пересоздание аккаунтов или ключей не нужны. Старый код с
полями модерации после миграции несовместим: откат только согласованным snapshot
и соответствующим кодом по OPERATIONS.
