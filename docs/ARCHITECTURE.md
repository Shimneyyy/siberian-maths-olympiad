# Текущая архитектура

Статическая база: a921c09. [Статус проверки](STATUS.md), [решения](DECISIONS.md).
Проект работает только в учебном контуре. Эта страница описывает реализацию;
предлагаемые изменения находятся в [TASKS](TASKS.md).

| Слой | Код и назначение |
| --- | --- |
| Страницы/API | [src/app](../src/app): Next.js App Router, серверные страницы, Route Handlers |
| Клиент | [src/components](../src/components): формы, таблицы, локальное состояние |

Основной путь записи: HTTP Origin/сессия/размер → схема входа → прикладные права и
повторная проверка пароля там, где требуется → транзакция/блокировки/revision →
предметная запись + аудит + предусмотренный outbox. Для staff пароль пока проверяет
HTTP-обёртка, а не сервис: открытый SEC03. Клиентская видимость кнопки не задаёт права.

## Роли и области доступа

Одна роль на аккаунт. Назначения организаторов хранятся отдельно от роли и могут
быть отозваны. Администратор один для всех годов; организатор может иметь несколько
площадок. Капитан — отношение к команде, не роль аккаунта.

| Операция | Студент | Главный | Организатор площадки | Технический администратор |
| --- | --- | --- | --- | --- |
| Профиль, ежегодное участие, команда | Свои по контракту | Исправление/отмена чужого участия после закрытия в своём году | Нет | Нет |
| Списки, CSV, явка | Нет | Назначенные годы | Назначенные очные площадки года | Нет |
| Площадки, организаторы площадок | Нет | Назначенные годы | Нет | Нет |
| Название/текущий выпуск | Нет | Назначенные годы; смена текущего требует прав на оба года | Нет | Нет |
| Сроки/ручное закрытие | Нет | Нет | Нет | Все годы |
| Назначение/отзыв/замена главного | Нет | Нет | Нет | По выбранному году |
| Объявления | Адресованные опубликованные | Черновики/публикация своего года | Нет отдельного права | Нет |
| Массовые письма | Получатель | Отправка в области года | Нет | Нет |
| Legacy/экспорт/импорт nsuhw | Своя декларация/метаданные | Работа с участниками своего года | Нет | Нет |
| Показ внешнего пароля | Только свой подтверждённый аккаунт | Нет права показа как владельцу | Нет | Нет |
| Результаты: импорт/публикация | Нет | Назначенные годы | Нет | Нет |
| Опубликованные результаты | Свои | Назначенные годы | Свои площадки | Нет |
| Дипломы: загрузка/публикация/скачивание | Свои текущие опубликованные | Назначенные годы | Нет | Нет |
| Обращения ПДн | Собственные | Нет отдельного права | Нет | Нет |

Массовый экспорт nsuhw главным может содержать отдельные внешние пароли; это
специальная операция из [контракта](contracts/NSUHW.md), не универсальный просмотр.
Provisioning выпуска, начальный bootstrap, обслуживание ключей/копий и рассмотрение
обращений — CLI локального оператора, а не дополнительные полномочия роли в сайте.

## Модель данных

- User: роль и подтверждение email; Account/Session/Verification/RateLimit — auth.
- StudentProfile: текущие ФИО/вуз/курс и revision. ConsentRecord: версия/хеш/назначение
  учебной отметки. Это не настоящее юридическое согласие.
- OlympiadEdition: год, название, текущий выпуск, расписание/ручное закрытие/revision.
- Venue: постоянная идентичность; EditionVenue: сведения и активность в выбранном году.
- EditionStaffGrant/VenueStaffAssignment: актуальные области организаторов.
- Participation: уникальный пользователь+год, формат/площадка либо дистанционная зона,
  самостоятельные снимки ФИО/вуза/курса, статус/revision и согласие того же владельца.
- Team/TeamMember и приглашения/передача капитанства: отдельный состав вуза/года.
  Attendance: отметка/revision/автор. ParticipationCorrection: причина отдельно от аудита.
- Announcement/MailBatch → OutboxEvent/OutboxJob: публикации и письма.
- LegacyNsuhwClaim/NsuhwLoginName/PreparedExternalAccount: декларация старого аккаунта,
  компоненты нового логина и шифрованные данные глобального внешнего аккаунта.
  NsuhwExportBatch/NsuhwImportBatch: ручная передача и импорт готового источника.
- ResultImportBatch/EditionProblem/IndividualResult/ResultProblemScore и отдельная
  ResultPublication: импортированные оценки и неизменяемая публикация пакета.
- DiplomaBatch/Item/Document/Version: проверенные файлы, документы и опубликованная версия.
- ConsentWithdrawalRequest: ручное обращение, не автоматическое удаление.
- AuditEvent: метаданные событий без копирования предметных ПДн и секретов.

Точные поля и связи — schema.prisma. SQL CHECK, составные FK, триггеры и частичные
индексы находятся также в миграциях; одной Prisma-схемы недостаточно для их восстановления.

## Целостность и конкуренция

Один текущий выпуск ограничен частичным индексом; формат участия — CHECK;
год/владелец/вуз — составными FK. Публикации и содержимое импортированных записей
защищены immutable-триггерами. Не отключать ограничения для очистки тестов.

Записи сравнивают revision; stale-формы получают конфликт. Год блокируется перед
участием; операции nsuhw используют User перед общей namespace-блокировкой.
Счётчик до транзакции не заменяет защиту лимитов команд. Полные правила и исключения
находятся в [контракте участия](contracts/PARTICIPATION.md).

Списки используют RepeatableRead и общий registrationsScope до COUNT/фасетов/строк.
Пагинация offset со вторичным id; страницы разных запросов не являются одним снимком.
Фасеты вуза/курса агрегируются SQL groupBy. Индекс editionId/fullName/id поддерживает
стандартную сортировку. Polling каждые 5 секунд не является SSE/WebSocket.

PrismaPg сериализует запросы одного транзакционного соединения, включая commit/
rollback; разные соединения остаются параллельными. DATABASE_POOL_MAX (20, 1–50)
задаётся в db.ts для app; maxWait — 3000 мс. CLI/worker создают свои адаптеры и
не наследуют этот app-параметр автоматически. [ADR адаптера](decisions/ADR-007-postgres-transaction-adapter.md).
