# Учебная эксплуатация

Статическая база a921c09. Только синтетическая loopback-БД, локальная почта,
закрытые runtime-каталоги. Production и реальные ПДн не разрешены.
[Политика хранения](DATA_LIFECYCLE.md), [условия ПДн](LEGAL_PLACEHOLDERS.md).

## Запуск и наблюдение

Подготовка app/Compose — [README](../README.md), Windows — [WSL](WINDOWS_WSL.md).
Процессы app/worker не являются частью snapshot: запускать заново после восстановления.
GET /api/health: 200 при доступной БД, иначе 503 без подробностей. Проверять свободное
место, доступность ключей/файлов, ClamAV, возраст/число READY/PROCESSING/FAILED jobs.
Не печатать .env/keyring/PDF/дампы/SMTP-ответы в логи или чат.

Worker с той же учебной .env: npm run worker; разовый цикл — npm run worker -- --once.
При сбое остановить только свой worker, восстановить SMTP и запустить снова.
Истёкшие lease подхватываются автоматически; не удалять jobs и не создавать новую
рассылку для каждого сетевого сбоя. FAILED требует разбора фиксированного кода.
Предметный повтор D06 — новое подтверждение и текущая аудитория.
[Доставка и её ограничения](contracts/COMMUNICATIONS.md).

## Ключи nsuhw

Остановить app/worker и операции записи; сохранить защищённые копии БД и ключей.
В .env должен быть DEMO_REGISTRATION=true; либо передать флаг команде:

```sh
DEMO_REGISTRATION=true npm run nsuhw:keys -- init
DEMO_REGISTRATION=true npm run nsuhw:keys -- add-version v2
DEMO_REGISTRATION=true npm run nsuhw:keys -- rewrap
```

Init сохраняет существующий валидный keyring. Потерянный keyring при шифрованных
записях нужно восстановить из копии; init не исправляет потерю. Версию v2 не
добавлять заново как новую, если она уже есть. Старые ключи сохранять: CLI удаления нет.
После частичного rewrap восстановить доступ к старым ключам и повторить.
Ротация KEK не меняет внешний пароль и не устраняет его компрометацию.
Утечка внешнего пароля требует ручной смены на nsuhw по согласованной процедуре.

BETTER_AUTH_SECRET нужен auth и HMAC импорта; его произвольная замена нарушает
работу существующих данных. Не создавать новый секрет/ключ ради входа или переноса.

## Копии и восстановление

Учебные цели: RPO 24 часа, RTO 8 часов. Наличие инструментов и небольшой drill
не доказывают ежедневные копии или RTO целевой инфраструктуры.
Нужны Docker и локальный PostgreSQL-контейнер из Compose; в CI PG_CONTAINER задаёт
контейнер для pg_dump/pg_restore. DATABASE_URL — loopback, synthetic DB.
App/worker и операции дипломов/ключей остановлены до согласованного snapshot.

```sh
DEMO_REGISTRATION=true npm run backup:create -- --confirmed-quiesced
# По умолчанию план, без удаления:
DEMO_REGISTRATION=true npm run backup:retention
DEMO_REGISTRATION=true npm run backup:retention -- --apply
# Только новая изолированная БД/каталог:
DEMO_REGISTRATION=true npm run backup:restore -- <UUID-копии> --confirmed-isolated
```

[create-demo-backup.ts](../scripts/create-demo-backup.ts),
[managed-backups.ts](../src/lib/managed-backups.ts),
[restore-backup.ts](../scripts/lib/restore-backup.ts).
Snapshot включает PostgreSQL/триггеры/миграции, DB-связанные проверенные файлы всех версий
дипломов через DiplomaItem, keyring и BETTER_AUTH_SECRET. Не включает orphan без
DB-метаданных. Проверяются синтетические email. Dump до 64 МиБ, до 1000 файлов
по 10 МиБ; dump + PDF суммарно до 128 МиБ, secret bundle отдельно до 64 КиБ.
Превышение даёт отказ, не усечённую копию.

PG dump, secret bundle и PDF шифруются AES-256-GCM с AAD UUID/назначения;
manifest аутентифицирован. .local/backups — 0700, файлы 0600;
master-key .local/backup-key вне backup-root. Хранить его защищённую копию отдельно.
Потеря ключа при непустом каталоге не приводит к переинициализации.
Это локальная учебная защита, не production-KMS или разделение прав ОС/KMS.

Restore создаёт новую smo_restore_<UUID> БД и .local/restores/<UUID> с приватными
PDF/keyring/runtime.env. Рабочую БД и корневую .env не заменяет. runtime.env содержит
секреты: не выводить/коммитить/пересылать. Проверить миграции, counts, владельца/год,
hash PDF, расшифровку синтетического пароля и вход с прежним паролем ЛК.
После старого snapshot применить миграции до старта совместимого кода.

Обращения после snapshot повторно применить из независимого журнала до доступа;
повторить истечение аудита. После проверок оператор отдельно выбирает runtime-конфиг.
До этого worker и доступ пользователей не включать. Restore CLI не выполняет
публикацию, автоматическое переключение или удаление предыдущей рабочей БД.

Retention удаляет лишь аутентифицированные управляемые копии возрастом не меньше
30 дней. Неизвестные/повреждённые файлы, подмена прав/ссылок дают отказ.
Бессрочные PDF/результаты/ключи этому сроку не подчиняются.
Scheduler инструменты не устанавливают: учебный оператор ежедневно создаёт копии
и запускает истечение. [Годовой аудит и обращения](DATA_LIFECYCLE.md).

## Откат

До обновления сохранить согласованный snapshot и предыдущий commit/build.
При сбое остановить app/worker, закрыть доступ, восстановить согласованный набор
БД/файлов/ключей в изолированном контуре и проверить до переключения.
Checkout старого кода не откатывает миграции. Не применять migrate reset и не
отключать immutable-триггеры. Несовместимый откат требует полного прежнего snapshot
с соответствующим кодом; зафиксировать потерю данных по RPO и уведомить ответственного.

## Пул и нагрузка

DATABASE_POOL_MAX применяется к app/db.ts: 20 по умолчанию, 1–50; maxWait=3000 мс.
Worker/CLI создают отдельные Prisma clients без чтения этого app-параметра.
Бюджет соединений всех процессов с резервом обслуживания задаётся отдельно.
Тайм-аут фонового списка 4000 мс не увеличивать ради прохождения нагрузки.

test:load создаёт временную БД/fixtures, затем изолированный оптимизированный
build/start на loopback; 5000 участников в каждом из двух годов и 200 подготовленных
активных сессий. Это не 200 одновременных password-login, браузеров или soak-test.
[Prerequisites и pipeline](TESTING.md), исторические измерения — [архив](archive/README.md).

## Условия перед production

| Условие | Незакрытая часть |
| --- | --- |
| ПДн/несовершеннолетние | Оператор, документы, цели/основания, бессрочное хранение, обращения |
| Ответственные | Эксплуатация, инциденты, восстановление доступа, решение о запуске |
| Провайдеры | Размещение БД/файлов/копий/почты в РФ, договоры и обработчики |
| Ключи | Настоящий KMS, отдельные права, ротация и восстановление |
| Сеть/почта | HTTPS/proxy/CDN/cache, безопасный IP, SPF/DKIM/DMARC, реальная доставка |
| Файлы | Свежесть AV, OS sandbox, ingress/storage quotas, production cleanup и максимальная нагрузка; PostgreSQL preparation leases уже есть |
| Наблюдение | Мониторинг/уведомления и независимый журнал обращений после snapshot |
| Копии | Scheduler, независимые ключи, RPO 24ч/RTO 8ч на целевых объёмах |
| Внешний nsuhw | Реальный формат/пароли/HTTPS и защищённая ручная передача |
| Допуск | Приёмка, процедура отката и отдельное разрешение запуска |

Учебный CI/документы не закрывают эти условия. Production guards не снимать в рамках
реорганизации документации. Публикация среды и merge в main не разрешены.

Ручное восстановимое перемещение orphan без окончательного удаления —
[жизненный цикл файлов](DATA_LIFECYCLE.md#ручная-изоляция-orphan-файлов).

## Проверка подготовленной среды

DEMO_REGISTRATION=true npm run ops:check проверяет Linux/Node 24, применённые
миграции, права keyring/файлов, PDF-service, возраст AV и соединение SMTP без письма.
JSON содержит только имена проверок/коды. Код 1 означает блокирующую проблему.
productionAccepted всегда false: инструмент не подменяет внешнюю приёмку.

PDF-worker/relay/updater описаны в [контракте](contracts/DIPLOMAS.md). Для proxy есть
[шаблон Nginx](../infra/nginx/site.conf.template). Подстановка только SMO_DOMAIN и
SMO_PROXY_SECRET; остальные $переменные Nginx сохраняются. Секрет proxy отдельный,
случайный и одинаковый в AUTH_TRUSTED_PROXY_SECRET приложения и конфигурации proxy.
App bind 127.0.0.1:3000, прямой публичный доступ закрыт. TLS/домен/почта/нагрузочные
пороги проверяются оператором на целевом хосте. Шаблон не установлен автоматически.
Ошибки proxy не должны содержать URL/адреса/токены; в шаблоне error_log отключён,
access_log содержит лишь status/method/time. Буферизация тел отключена, чтобы не
создавать временные копии CSV/паролей/дипломов на proxy-диске.
