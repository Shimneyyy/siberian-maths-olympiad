# ADR-014: создание выпуска через кабинет администратора

Принято 21 ноября 2026. Источник — запрос пользователя добавить и реализовать
создание выпуска через сайт после обсуждения production-процесса. Уточняет
[ADR-001](ADR-001-roles-and-scopes.md): TECHNICAL_ADMIN получает право создания года.

Первого технического администратора по-прежнему создаёт оператор через CLI;
публичной регистрации или второго администратора нет. В кабинете администратор
создаёт выпуск, затем задаёт сроки и назначает главного организатора. Главный
продолжает управлять площадками/названием/текущим выпуском в своей области.

Создание требует подтверждённой сессии администратора, текущего пароля с общим
admin-reauth limit и явного подтверждения. Actor берётся только из сессии;
роль повторно проверяется внутри транзакции под блокировкой создания.

Принимаются UUID попытки, год 1–9999 и название 1–200 символов. Новый выпуск не
становится текущим, не получает сроки и назначения автоматически. Другой UUID
для существующего года даёт конфликт; настройки прежнего выпуска не переписываются.
Повтор того же UUID/автора/исходного содержимого возвращает созданный выпуск даже
после последующих изменений его настроек. Аудит атомарен и хранит ID/год/хеш
исходного запроса без пароля и названия. Если исходная запись аудита уже удалена
по годовому сроку хранения, старый UUID даёт безопасный конфликт, а не повторное
создание или перезапись. Данные выпуска при этом сохраняются.

CLI edition:create остаётся операторским инструментом. Новая операция использует
существующие таблицы; дополнительная миграция не нужна. Доступ к участникам,
результатам, дипломам и внешним паролям администратору не добавляется.
