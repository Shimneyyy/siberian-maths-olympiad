# ADR-013: изолированная проверка файлов и ранняя квота

Инженерное решение 21 ноября 2026, задачи SEC05/SEC04.

Landlock недоступен в доступной среде (ENOSYS), bwrap ранее не смог создать UID
namespace. Вместо запуска парсера рядом с ключами используется отдельный контейнер
без host mounts, исходников сайта, секретов и хранилища. Непривилегированный UID,
read-only root, dropped capabilities, no-new-privileges, CPU/memory/PID limits,
внутренняя сеть. На хост опубликован только фиксированный TCP relay: он передаёт
байты к единственному parser endpoint, не разбирает PDF и не выбирает upstream.
Приложению доступ к Docker socket не нужен. Fallback на неизолированный парсер нет.

Квота 1 загрузка/actor и 2/БД захватывается до чтения multipart; чтение ограничено
размером и 30 секундами. Приватный parser/ClamAV проверяют ту же копию/hash.
Возраст загруженных AV-баз проверяется VERSION до INSTREAM; отсутствие/неверный
ответ/превышение заданной границы не дают CLEAN. Обновление баз — отдельный сервис.

Локальная изоляция и отказ на stale проверяются тестами. Они не доказывают свежесть
доступных баз или приёмку целевого production-хоста. Подробности и размеры —
[дипломы](../contracts/DIPLOMAS.md), [безопасность](../SECURITY.md).

Уточнение пользователя 21 ноября: при неудачной загрузке ничего не публикуется,
при необходимости студент обращается к организатору самостоятельно. Автоматическая
уборка/удаление orphan и автоматические обращения не включены. Обычный отказ
откатывает batch, созданные файлы удаляются по возможности; crash-остатки разбираются
ручным техническим инструментом. Исторические DB-связанные PDF сохраняются.
