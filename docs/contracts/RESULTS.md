## Файловый контракт

Личные результаты, сопоставление по точному логину nsuhw участия
выбранного года. Не ФИО. Командный импорт имеет [отдельный контракт](TEAM_RESULTS.md); внешняя общая таблица не интегрируется.

```csv
ФИО,Курс,Вуз,Логин,Задача 1,Задача 2,Сумма баллов
Синтетический участник,2,Учебный вуз,synthetic.example,0,,17
```

UTF-8, BOM необязателен, запятая, кавычки с удвоением, LF/CRLF/CR. От 1 до 50
столбцов Задача 1…N подряд; затем Сумма баллов (или прежнее Сумма).
Приз — необязательный последний столбец. Поддержан прежний формат Логин,…,Сумма,Приз.
Перед задачами обязателен Логин; ФИО/Курс/Вуз необязательны и могут идти в любом порядке.
Повторные/неизвестные заголовки запрещены. Метаданные показаны в preview, не меняют
профиль/годовой снимок и не используются как запасной ключ сопоставления. Число задач фиксирует первый успешный
импорт выпуска для обоих видов. После импорта редактора задач нет.
Оценки и сумма — целые 0…2147483647 либо пустые. Пусто отличается от 0; сумма
готовая, не пересчитывается и не сверяется автоматически с суммой задач.
Приз — текст до 200 символов, пусто → null. Формулы/знаки/дроби/экспонента не принимаются.

Файл до 512 КиБ, 10000 строк, ячейка до 1024 символов, логин до 254.
XLS/макросы не поддержаны. Повреждённые заголовки/CSV или превышение структурных
лимитов отвергают файл целиком; ошибки значений из разобранных строк — построчно.
Все дубли участника в файле отклоняются. Существующий результат того же вида
не заменяется; preliminary и final имеют отдельную уникальность участие+вид.

## Preview и apply

/cabinet/results-import; POST /api/results/import/preview и /apply.
Только главный назначенного года, подтверждённый email и учебный режим.
Apply требует пароль, общий correction-reauth 5/мин и явное подтверждение.
Origin/сессия/схема/no-store — общий API handler. Оба endpoint допускают JSON
до 1 МиБ; такой же лимит есть у двух маршрутов импорта аккаунтов nsuhw.
Обычный JSON — 16 КиБ, multipart дипломов имеет отдельный лимит.

Новый аккаунт с confirmedAt либо сразу самовведённый старый логин связывается с участием выбранного
года по точному логину после trim CSV; регистр старого логина не нормализуется.
Неподтверждённый новый аккаунт/неизвестное/неоднозначное соответствие — общий PARTICIPANT_UNAVAILABLE.
Студент должен иметь подтверждённый email и @example.test. Отменённое участие
не исключается из импорта, но результат не восстанавливает статус/явку.

Preview не пишет задачи/результаты/публикации. selectionHash связывает исходник,
вид/год, соответствия и состояние. Apply блокирует выпуск, заново проверяет права
и hash. При stale нужен новый preview; сетевой повтор сохраняет UUID.
[Поведение формы при отказах и потере ответа](../SECURITY.md#сбои-форм-импорта).
Тот же UUID/автор/CSV/вид/год возвращает прежний итог, изменённое содержимое конфликтует.
Частичность — только ошибки строк; DB/аудитный сбой откатывает весь batch.
Параллельные загрузки не перезаписывают участие/вид, unique и блокировка защищают гонку.

Хранятся batch/hash/счётчики/ошибки строк, задачи, результаты и оценки.
ФИО/курс/вуз из CSV служат предпросмотру и отдельно в результат не записываются. CSV не
сохраняется на серверный диск/в БД. Аудит — UUID/вид/счётчики, без логина/баллов/приза.
Составные FK/CHECK защищают год/оценки, immutable-триггеры — содержимое импорта.
Импорт не публикует, не ставит email и сам не даёт студенту результат.

## Review, публикация и чтение

POST /api/results/import/review доступен только главному года. Он читает batches
и строки выбранного batch по 25; этот reader не используется для выдачи студентам.
POST /api/results/publish публикует отдельный выбранный batch с паролем/лимитом/
подтверждением главного. Под блокировкой года ResultPublication, аудит и outbox
пишутся атомарно. Повтор не дублирует письмо. Публикация неизменяема.

POST /api/results/search и /cabinet/results выдают только опубликованное:
студенту своё, главному назначенный год, организатору свои площадки через
registrationsScope. Техническому администратору доступа нет. По 25 строк.
После собственных опубликованных final студенту сервер исключает его preliminary;
final другого участника его preliminary не скрывает. Организаторам доступны
опубликованные виды в их области. Общего студенческого рейтинга нет.

История /cabinet/history — только собственные опубликованные записи всех годов,
год по убыванию, 25 на странице; final скрывает preliminary своего участия/года.
Номинация — существующее поле Приз, формулы ранга/наград не вводятся.
Письмо сообщает о доступности без баллов/приза. Worker — [COMMUNICATIONS](COMMUNICATIONS.md).

Исправление/отзыв выполняются через версии и отдельное подтверждение (ниже),
CSV не перезаписывает оригинал автоматически. Результаты хранятся бессрочно по учебной политике; [жизненный цикл](../DATA_LIFECYCLE.md).
Сценарии result-imports/communications/data-lifecycle — [TESTING](../TESTING.md).

## Исправление и отзыв

[ADR-011](../decisions/ADR-011-result-corrections-and-revocation.md),
[result-documents.ts](../../src/lib/result-documents.ts). Главный своего года открывает
«Версии и отзыв результатов» в /cabinet/results-import либо /cabinet/team-results-import.
POST /api/results/documents — по 25 документов, последние 50 версий/событий каждого;
предыдущие версии сохраняются в БД. Студент/технический администратор этот DTO не получают.

POST /api/results/amend: documentId/editionId/revision/id, scores 1–50 значений,
total, prize, reason 3–2000 символов, пароль и confirmed. Число задач исходника
сохраняется; ноль отличается от null. Создаётся неизменяемая версия, видимый результат
не меняется. Для личного результата исходный batch должен быть опубликован прежде
исправления. Повтор того же UUID/содержимого возвращает прежнюю версию.

POST /api/results/release: те же scope/revision/proof, id, versionId и action
PUBLISH либо REVOKE. Публикуется последняя версия, в том числе явно восстанавливается
отозванная; старую версию поверх новой опубликовать нельзя. Отзывается только текущая
активная версия; reason обязателен. Событие, указатель, аудит и outbox транзакционны.
Нельзя переносить версии между владельцами/годами. Повтор старого batch-publish не
оживляет отозванное достижение. Новый видимый final скрывает preliminary отдельно
для личного результата и для конкретной команды; отозванный final не скрывает preliminary.

ResultRecipient хранит снимок получателей/ФИО/курсов/вузов. Результаты и история читают
только currentVersion с withdrawn=false. Организатор площадки получает свой scope
до count/pagination и видит только получателей своей области. Причины не передаются
участнику и не копируются в аудит/письма. Оригинальные IndividualResult/ResultProblemScore
остаются immutable. Миграция 20261121090000 переносит существующие публикации в версию 1.
