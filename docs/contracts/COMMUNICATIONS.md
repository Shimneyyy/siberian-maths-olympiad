# Объявления, рассылки и outbox

Статически сверено с a921c09. Источники: [announcements.ts](../../src/lib/announcements.ts),
[mail-batches.ts](../../src/lib/mail-batches.ts), [outbox.ts](../../src/lib/outbox.ts),
[mail-template.ts](../../src/lib/mail-template.ts), [worker](../../scripts/mail-worker.ts).
Решения публикации — [ADR-004](../decisions/ADR-004-publication-and-versioning.md).

## Объявления

Главный с действующим назначением на год создаёт/правит черновик для года либо
площадки этого года. Изменения проверяют пароль/общий correction-reauth лимит.
Публикация требует отдельного подтверждения; опубликованный текст неизменяем,
включая SQL UPDATE/DELETE. Исправление — новым объявлением, API удаления нет.
Текст выводится как текст, не HTML. Студент читает адресованные опубликованные
объявления по своему участию/площадке; отмена участия не исключает адресата.
Дистанционному доступны общие объявления года. Отдельного права чтения/публикации
для организатора площадки или технического администратора нет.

Флажок «Отправить уведомление по email при публикации» создаёт задания для рассылки. Статус публикации показывается организатору. Публикация, аудит и
outbox атомарны; повтор не дублирует событие. Письмо предлагает открыть ЛК,
не копирует текст объявления и секреты.

## Массовая рассылка

Главный выбирает год/площадку, тему/текст, подтверждает аудиторию и текущий пароль.
Только переменные name/year/university/team/venue; обычный текст. Значения не
интерпретируются повторно как шаблон. Нет переменных внешнего пароля/логина/токена.

UUID запроса связывает содержимое: сетевой повтор с тем же UUID не создаёт новую
рассылку, изменённое содержимое конфликтует. Не менять UUID автоматически при
сетевой ошибке. Предметный повтор создаёт новый UUID, сохраняет прежние шаблон и
область, требует нового подтверждения и заново выбирает актуальных адресатов,
включая отменившихся. Старые OutboxJob не копируются.

## Доставка

enqueueEmail вызывается внутри предметной транзакции с actor из сессии и серверной
аудиторией. Источник/версия/адресат защищены от повторного создания. Worker перед
отправкой проверяет действующее назначение автора и актуальную область адресата;
устаревшая площадочная адресация не должна доставляться после переноса.

Lease — 90 секунд, до пяти попыток с задержками, затем FAILED с фиксированным кодом.
Истёкшую аренду подхватывает следующий worker; fencing защищает от устаревшей квитанции.
Один цикл обрабатывает до 20 заданий, --once выходит после него. npm run dev запускает обработчик вместе с Next.js при включённом учебном режиме. Учебный режим
обязателен, production запрещён; получатели только синтетические.

Доставка как минимум один раз: crash после SMTP-accept до записи квитанции может
дать повтор. Message-ID стабилен, абсолютная однократность email не гарантируется.
Статусы READY/PROCESSING/SENT/FAILED/CANCELLED определены схемой.
Даже SMTP-accept/SENT не доказывает получение письма человеком.
Ошибка SMTP хранится фиксированным кодом, без текста ответа/ПДн.

Уведомления предусмотрены для публикации результатов/дипломов, подтверждения
внешнего аккаунта и переноса. Пароли, PDF и токены в предметный outbox не включаются.
Auth OTP/reset отправляются библиотекой через mail callback и не являются этим outbox.

## API и проверка

POST /api/announcements, /publish, /search; POST /api/mail-batches и /search.
Правила Origin, сессии и no-store — [SECURITY](../SECURITY.md).
Сценарии announcements/outbox и test:communications проверяют транзакционность,
повторы, отзыв и SMTP в Mailpit. [Команды](../TESTING.md); этот контракт не сообщает
новых результатов runtime или реальной доставки внешним почтовым провайдером.
