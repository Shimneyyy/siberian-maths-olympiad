# Аккаунты nsuhw

Обновлено 20 ноября 2026 после 66e7778. [ADR-003](../decisions/ADR-003-nsuhw-credentials.md),
новое [ADR-009](../decisions/ADR-009-self-reported-login-and-results.md).
Связь сайтов — переход, без API/SSO/синхронизации. Внешний аккаунт относится к
пользователю и сохраняется между годами; ежегодная заявка не генерирует его заново.
Пароли ЛК и nsuhw раздельны; пароль ЛК не экспортируется.

## Старый аккаунт

[legacy-nsuhw.ts](../../src/lib/legacy-nsuhw.ts), [правила](../../src/lib/legacy-nsuhw-rules.ts).
Студент вводит свой старый логин при signup либо в разделе «Аккаунт nsuhw».
POST /api/nsuhw/legacy принимает только login, без согласия на проверку/пароля nsuhw.
Нужны собственная подтверждённая STUDENT-сессия и учебный режим; при signup запись
внутри транзакции выполняется до подтверждения email. Логин используется сразу.
Организатор не проверяет принадлежность; экран, review/approve API и поля approved*
удалены. Новая миграция сохраняет все прежние введённые логины, в том числе ожидавшие
проверки; ни один из них не требует отдельной активации.

Валидируется непустой формат/длина/управляющие символы, trim без смены регистра или
транслитерации. Внешних запросов проверки нет. Самоввод не доказывает владение внешним
аккаунтом. Совпадение логина у нескольких пользователей допустимо; импорт результатов
и дипломов отвергает неоднозначное соответствие в выбранном году, не выбирает первого.

Собственный сохранённый логин запрещает генерацию замены; prepared того же пользователя
запрещает его молчаливую замену старым логином. Повтор того же login идемпотентен;
другой login конфликтует. Редактирование ошибочно введённого логина/перепривязка
пока отдельно не реализованы. Пароль старого аккаунта не собирается и не раскрывается.

## Новые данные

[nsuhw-login-names.ts](../../src/lib/nsuhw-login-names.ts),
[правила имён](../../src/lib/nsuhw-login-name-rules.ts),
[prepare-nsuhw.ts](../../src/lib/prepare-nsuhw.ts).
ФИО сохраняется в исходном написании. Отдельные имя/фамилия логина — 1–80 ASCII-букв
A–Z, trim; без пробелов/цифр/знаков. Автоматического разбора ФИО/транслитерации нет.
Preview smc.i.petrov не резервирует имя и не проверяет внешний сайт.

Signup без legacy атомарно готовит кандидата с профилем/учебной отметкой. Старый
пользователь без legacy/prepared может сохранить компоненты и отдельно подтвердить
подготовку с nameRevision. User lock защищает повтор; общий namespace lock учитывает
все известные самовведённые старые логины и prepared без учёта регистра новых кандидатов.
Коллизии: smc.i.petrov, smc.i.petrov2, smc.i.petrov3. Это локальная уникальность по
известным данным, не проверка всех аккаунтов nsuhw. Финальный логин неизменен при
правке профиля; после подготовки компоненты не переименовывают аккаунт.

Пароль — 24 случайные ASCII-буквы/цифры с верхним/нижним регистром и цифрой,
randomInt без modulo bias. Сразу шифруется, не выдаётся при signup. Ошибка ключа
откатывает транзакцию; сбой OTP после commit отличается от rollback и позволяет
повторно запросить письмо. Совместимость параметров с настоящим nsuhw не принята.

## Шифрование и обслуживание

[envelope.ts](../../src/lib/external-secrets/envelope.ts),
[storage.ts](../../src/lib/external-secrets/storage.ts),
[local-keys.ts](../../src/lib/external-secrets/local-keys.ts).
AES-256-GCM, отдельный DEK на секрет, обёртка версионным KEK. AAD включает service,
purpose, accountId, userId, login и credentialVersion, без года. Keyring отделён
от БД и BETTER_AUTH_SECRET. DTO/логи/outbox не содержат envelope/ключей/plaintext.

DemoLocalKeyProtector требует учебный режим, запрещает production и native Windows;
файл keyring 0600, по умолчанию .local/nsuhw-keyring.json. Init не заменяет потерянный
ключ при шифрованных записях; add-version/rewrap сохраняют старые ключи.
Rewrap меняет обёртку DEK, не пароль. При сбое ранние строки могли завершиться:
восстановить доступ к старым ключам и повторить, не удалять их.
Остановить app/worker на обслуживание. [Команды](../OPERATIONS.md).
JS-строки не обещают гарантированного стирания памяти. Production KMS отсутствует.

## Экспорт новых аккаунтов

[nsuhw-export.ts](../../src/lib/nsuhw-export.ts), /cabinet/nsuhw-export.
Главный назначенного года выбирает действующих участников с подтверждённым email и
prepared без confirmedAt; отменённые/старые/готовые не попадают в файл нового создания.
ФИО — снимок участия. Готовые/старые логины для повторного участия показаны отдельно,
без внешних паролей. Скачивание требует scoped reauth/подтверждения и selectionHash.

CSV UTF-8 BOM, запятая, кавычки, CRLF; заголовки Логин,пароль,ФИО. До 10000 записей;
XLS нет. Опасное spreadsheet-начало поля блокирует выгрузку, не изменяет значение.
Нужен HTTPS либо учебный loopback. CSV существует в памяти attachment и скачанном
файле пользователя, не в серверном временном файле. Private/no-store/no-cache,
no-referrer/nosniff/sandbox. Не отправлять обычной почтой/общей ссылкой.

Скачивание не подтверждает создание. После успешной ручной загрузки всех строк
ответственный отдельно подтверждает конкретный batch с паролем. При частичном успехе
не подтверждать весь пакет: автоматического разбирательства конфликтов нет.
Batch содержит идентификаторы/версии, не пароль/ФИО. Подтверждение/аудит/outbox
атомарны, повтор не дублирует письмо. Отмена после скачивания не отменяет факта
внешнего создания и не восстанавливается подтверждением. Локальный CSV удалить
после успешной передачи. Тестовая отметка не доказывает реальную работу nsuhw.

## Импорт готового источника

[account-import-csv.ts](../../src/lib/account-import-csv.ts),
[account-imports.ts](../../src/lib/account-imports.ts), /cabinet/nsuhw-import.
CSV UTF-8, необязательный BOM, запятая/кавычки; точные заголовки:

```csv
ID пользователя ЛК,логин nsuhw,пароль nsuhw
```

До 512 КиБ, 1000 строк; пароль 1–128 символов без управляющих, без trim/нормализации.
Владелец — подтверждённый студент @example.test с участием выбранного года.
Существующие prepared/любая legacy запрещают замену: обычная новая signup уже имеет
prepared и для этого импорта не подходит. Сопоставление по UUID, не ФИО.
Все дубли userId/логина ошибочны, новые коллизии сравниваются без регистра;
существующее написание не меняется. Повреждённое CSV-обрамление отклоняет файл,
ошибки корректно разобранных строк допускают частичное применение.

Preview выдаёт номера строк, разрешённые имена, коды/fingerprint без паролей,
CSV и внешних логинов. Apply требует пароль/лимит/подтверждение действующего
проверенного источника. Повторно проверяются scope/hash под блокировками:
год → scoped Users в стабильном порядке → namespace. Чужие UUID отклонённых строк
не блокируются только потому, что оказались в файле.
UUID связан с автором/годом/HMAC источника; тот же запрос возвращает прежний итог.
[Поведение формы при отказах и потере ответа](../SECURITY.md#сбои-форм-импорта).
HMAC с отдельным purpose использует BETTER_AUTH_SECRET; это не шифрование пароля.
E01 шифрует пароль отдельно. Сбой DB/ключа/аудита/outbox откатывает весь batch;
частичность относится к ошибкам строк. Batch immutable, исходник на диск/в БД не пишется.
Импорт готового источника сразу подтверждает эти внешние данные, но не создаёт их
на внешнем сайте. Уведомление без секретов, выдача владельцу — ниже.

## Показ владельцу

[nsuhw-secret-auth.ts](../../src/lib/nsuhw-secret-auth.ts),
[reveal-nsuhw.ts](../../src/lib/reveal-nsuhw.ts), POST /api/nsuhw/secret.
Только собственный подтверждённый студент после confirmedAt, с новым вводом пароля
ЛК/подтверждением/лимитом 5 за минуту. В теле нет выбора userId/accountId.
В транзакции заново проверяются владелец/готовность, до ответа обязателен аудит.
Ключевой/аудитный сбой не выдаёт секрет. Повторный просмотр разрешён; смена пароля
ЛК не меняет nsuhw. Неизвестный legacy-пароль не восстанавливается генерацией.

Ответ POST/no-store; нет SSR/URL/storage/mail/outbox/log. Клиент скрывает по кнопке,
через минуту, blur/visibility/pagehide. Это не гарантирует стирание увиденного секрета.
Реальный импорт nsuhw, защищённый канал и production-KMS требуют отдельной приёмки.
Сценарии legacy/external-secrets/nsuhw-delivery/account-imports, communications — [TESTING](../TESTING.md).
