# E09 — приватные файлы: границы и подготовка

## Принято до этой задачи

Q09: приватные PDF участника конкретного года, несколько документов, отдельная
публикация и уведомление. Замена с аудитом и прекращением доступа к старой версии.
Загружает/публикует главный организатор. Командный диплом можно выдать участникам
по отдельности. Учебная разработка использует локальные приватные файлы (Q13);
production-хранилище, правовые сроки и эксплуатация ещё не утверждены.

9 ноября 2026 направлены уточнения:
- начать с одного PDF за запрос и явного выбора участника/года, без ZIP/массовой
  загрузки; предложен предел 10 МиБ;
- при замене сохранять старый опубликованный диплом до отдельной публикации нового,
  затем выдавать только новый и отправлять уведомление.

Последующим ответом от 9 ноября подтверждены массовый ZIP, 10 МиБ на PDF,
50 МиБ на ZIP, до 1000 PDF и сохранение старого диплома до публикации замены.
Первоначальное предложение только одиночной загрузки заменено массовым ZIP. Новые загрузки/скачивания
и замена дипломов не включены. E09 и E10 не завершены.

## E09a — учебный карантин

`src/lib/private-files/quarantine.ts`: внутренний DemoQuarantine, без маршрутов,
UI, runtime-конфигурации и таблиц БД. Он не подключён к приёму пользовательских
файлов. Успех put означает только запись байтов в карантин, не разрешение выдачи.
Нет проверки PDF, антивируса или подтверждения безопасности файла.

Оператор будущего сервиса задаёт отдельный приватный каталог и предел maxBytes.
Значение обязательное; бизнес-лимит диплома не задан по умолчанию. Техническая
граница параметра от 1 байта до 64 МиБ ограничивает выделение памяти, а не утверждает лимит
пользовательского PDF. В тестах выбран 1 КиБ, только синтетические байты.

Каталог создаётся с 0700; существующий каталог с групповыми/публичными правами
отвергается, права чужого каталога автоматически не меняются. Realpath исключает
symlink корня/предков. Папки public, .next и out текущего приложения запрещены.
Будущее размещение не должно попадать в сторонние статические маршруты reverse proxy;
это невозможно определить только по пути локального каталога.

Файл создаётся эксклюзивно с 0600/O_NOFOLLOW, UUIDv4 и суффиксом .quarantine,
без исходного имени, перезаписи и public URL. Копия входных байтов фиксируется до
хеширования/записи. Запись синхронизируется; при сбое созданный файл удаляется
по возможности, исходная ошибка наружу заменяется фиксированным кодом.
При аварии процесса возможен orphan: его lifecycle/уборка пока не реализованы.

Внутреннее чтение требует UUID и ожидаемый SHA-256 от будущего доверенного сервиса.
O_NOFOLLOW/O_NONBLOCK и fstat отвергают symlink, hardlink, каталоги/FIFO и открытые
права; длина ограничена, изменения/усечение/подмена обнаруживаются по длине/хешу.
Hash сам по себе не является авторизацией или антивирусной отметкой. Ошибки не
содержат путей/байтов. Содержимое не шифруется: учебный backend закрыт в production
даже с DEMO_REGISTRATION=true. От root/процесса с тем же доверенным UID файловая
изоляция не защищает; production требует отдельной модели хранения и ключей.

## Необходимые следующие части E09/E10

После уточнений: строгая проверка размера/типа/MIME/сигнатуры и структуры PDF,
настоящая проверка антивирусом с fail-closed при ошибке/недоступности, метаданные
карантин/проверен/отклонён в БД, связь участник+год, серверные права для каждого
действия и скачивания. Не выдавать файл по одному знанию ключа.
Отдельно реализовать согласованные публикацию/замену, аудит и outbox, защиту от
orphan при сбое БД/файловой записи и сроки очистки. Не сохранять файлы в public
или включаемый артефакт Next.js. Не заменять реальное сканирование заглушкой.
Реальные дипломы/ПДн пока не принимать; юридические документы временные.

## E09b — предварительная проверка ZIP (9 ноября 2026)

Пользователь принял: ZIP с PDF в корне, имя `<точный логин nsuhw>.pdf`, год задаёт
главный, предпросмотр и частичное применение корректных файлов, отдельная публикация.
Несколько документов одному участнику — отдельными пакетами. Размеры и замена
подтверждены: 10 МиБ/PDF, 50 МиБ/ZIP, 1000 PDF; старый доступен до публикации нового,
затем закрывается и приходит уведомление. Это закрывает вопросы размеров/замены.

previewDiplomaZip — пока только внутренняя функция, не API загрузки. yauzl 3.4.0
читает архив последовательно, без записи/извлечения на диск. Предпросмотр возвращает
индекс, имя, точный логин, размер, SHA-256 и код ошибки. Нет поиска пользователей,
привязки к году, сохранения, PDF-структурной проверки или антивирусной отметки.
Первые пять байтов %PDF- — лишь предварительный признак, не доказательство безопасности.

Заголовки/CRC/фактический размер проверяются, поддержаны stored/deflate. Директории,
вложенные пути/архивы, ссылки/специальные объекты и неподходящие имена не допускаются.
Все дубли точного логина отклоняются, включая не-PDF или symlink с таким же именем;
регистр логина не нормализуется, регистр расширения PDF не меняет идентичность.
Повреждение ZIP/CRC, шифрование, нарушение количества/размеров/коэффициента распаковки
или тайм-аут отклоняют архив целиком без частичного результата. Ошибки подходящего
по структуре архива отражаются пофайлово. Внешние ошибки фиксированные, без байтов.

Обязательный limits позволяет будущему сервису задавать политику. Экспортирован
DIPLOMA_ZIP_LIMITS с принятыми размерами; общий распакованный максимум равен
1000×10 МиБ. Дополнительные технические предохранители — коэффициент 200 и 60 секунд;
при отказе большой пакет следует разделить. Вся распаковка идёт потоково, содержимое
не удерживается в итоговом manifest. Входной ZIP копируется один раз (до 50 МиБ).

E09/E10 пока не завершены: эту функцию нельзя использовать как разрешение выдачи
диплома. Нужны настоящий сканер, разбор PDF, DB/области доступа, upload/публикация/
скачивание/замена и очистка карантина. Все примеры/тесты синтетические.

## E09c — настоящий учебный ClamAV

В Compose добавлен отдельный профиль files с ClamAV 1.5.4, образ закреплён digest
sha256:6d87c712e3391e13c1ba6e05dfb074d4b1ddb5a6834b23bb9da990d2a4ef042a.
Порт доступен только на 127.0.0.1:3310. Собственный минимальный clamd-demo.conf
ограничивает поток 10 МиБ, вложенность/объём сканирования, включает AlertExceedsMax
(лимит не означает CLEAN). До 2 потоков, 2 GiB RAM; compose healthcheck — реальный ping.

scanWithClamav отправляет только байты через INSTREAM, без имён/путей/логинов.
Возвращает CLEAN или REJECTED, ошибки/неизвестные/ранние ответы, EOF, отказ соединения,
тайм-аут и превышения дают FILE_SCANNER_UNAVAILABLE. Ответы сканера не возвращаются
пользователю/в лог. Стриминг по 64 КиБ с ожиданием записи; общий тайм-аут 30 секунд.
Учебный флаг обязателен, production всегда запрещён. Это ещё не обработчик загрузки.
CLEAN означает только отрицательный результат этого сканирования; это не проверка
структуры/пассивности PDF, не авторизация, не разрешение публикации и не гарантия
отсутствия всех угроз. Статус нужно будет связать с hash конкретной версии в БД.

Реальная проверка: ClamAV принял доброкачественные синтетические байты и отверг
стандартную EICAR-тестовую строку. Положительные вердикты не имитировались. Отдельные
имитаторы TCP проверяют только сбои/мусор/тайм-аут и не выдают тестовый CLEAN.
База в образе: daily 28171 от 1 ноября 2026; к 9 ноября она не считается актуальной
для production. Обновление freshclam, его доступ и контроль свежести НЕ проверены:
этот учебный запуск использует подписанные базы из закреплённого образа. Production
потребует управляемых обновлений и отдельной приёмки, а не ослабления TLS/проверок.

Локально: docker compose --profile files up -d --wait clamav, затем npm run test:files.
Остальной Compose без профиля files не запускает сканер. Для остановки сканера:
docker compose --profile files stop clamav. Приложение/worker загрузок пока не
используют его: PDF-разбор, права, metadata/upload/download и публикация дипломов
ещё впереди. E09/E10 по-прежнему не отмечаются завершёнными.
