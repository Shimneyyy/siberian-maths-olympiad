9 ноября 2026 пользователь уточнил: удалить только TOTP/двухфакторную проверку,
сохранив обычный вход по email и паролю и права ролей. Это отменяет прежнюю
часть Q13/B07/F02b о MFA. Исходный PRD не менялся.

## Изменения

- Удалены Better Auth twoFactor и клиентский плагин, настройка фактора, резервные
  коды, промежуточная форма/страница /two-factor и перенаправления к ней.
- Все прежние /api/auth/two-factor/* закрыты существующим allowlist (404/no-store).
  /api/me больше не возвращает twoFactorEnabled. Кнопка выхода сохранена.
- Убраны требования фактора из навигации, страниц, API и общих серверных политик.
  Роли, verified email, назначения годов/площадок, владение, повторная проверка
  пароля, лимиты, Origin/CSRF, аудит, SQL-инварианты и outbox сохранены.
- Новая миграция 20261109130000_remove_totp удаляет таблицу TwoFactor (секреты
  и резервные коды) и колонку User.twoFactorEnabled. Прежние миграции неизменны.
  Пользователи, пароли, сессии, назначения и предметная история не изменяются.
- Тестовые пользователи входят без настройки фактора. Негативные сценарии
  неподтверждённого email, чужих областей и неверного пароля сохранены.
  Приёмка резервных кодов заменена проверкой отсутствия старого функционала;
  добавлен переход с заполненной прежней схемы. Restore-drill проверяет
  сохранение паролей ЛК и auth/HMAC-секрета вместо удалённых факторов.
- Обновлены README, AGENTS, ручной прогон, эксплуатация и действующие контракты.
  Каталог work/ со вспомогательными скриптами и логами исключён из Git.
  Исторические журналы и прежние результаты проверок сохраняются с явной пометкой.

## Обновление существующей учебной среды

Остановите app/worker, сохраните согласованную резервную копию БД/файлов/ключей.
Сохраните существующие .env, BETTER_AUTH_SECRET и keyring. В checkout work:

```sh
npm ci
npm run db:generate
npm run db:migrate
npm run build
npm run check:build
```

Затем запускайте приложение/worker обычным способом. Не запускайте старый код
после удаления колонок. Аккаунты с ранее включённым TOTP входят по прежнему
email/паролю; сброс пароля и ручная правка пользователей для перехода не нужны.
Незавершённый второй шаг старого входа надо начать заново с /login.
Остаточные challenge-cookie не дают доступа: плагин и его endpoints удалены,
обычная сессия по-прежнему обязательна. Хешированные временные Verification
с ограниченным TTL не преобразуются в сессии и не содержат секретов фактора.

Удалённые секреты невозможно восстановить из новой схемы. Откат — целый
согласованный snapshot до миграции вместе с соответствующим старым кодом,
по OPERATIONS.md; один checkout старого кода недостаточен. Старые backup могут
содержать факторы: хранить их по прежней политике, не редактировать dump вручную.
При восстановлении старой копии для нового кода применить миграции до запуска.
