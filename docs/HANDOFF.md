# Передача проекта

## Состояние на 6 ноября 2026 года

Пользователь разрешил начало разработки. Три роли, без отдельного администратора;
баллы по задачам обязательны, совмещения ролей нет, несовершеннолетние допускаются.
Аккаунты nsuhw сохраняются между годами, новым участникам будут генерироваться данные;
между сайтами только кнопка, API/SSO нет. Все решения — DECISIONS.md.

Подготовлена первая часть технической основы:
- Next.js 16.4.5, React 19.3.1, TypeScript, Tailwind 4, базовый Button в стиле shadcn/ui.
- Русская стартовая страница с честным статусом готовности и переходом на nsuhw.
- PostgreSQL 17 и Mailpit в Compose с локальными портами.
- Prisma 7.10.1 и pg adapter; User с одной ролью, профиль, вуз, курс, согласие и выпуск.
- Первая SQL-миграция, демонстрационный seed без ПДн, четыре интеграционных теста БД.
- Серверный Prisma singleton, health endpoint; CI с сервисом PostgreSQL.
- README с командами, lockfile и настройки инструментов.

Вход, регистрация, MFA, роли/назначения на уровне запросов, рассылки, участие,
результаты, дипломы и nsuhw ещё не реализованы. Enum роли не является авторизацией.
Полный этап 1 (B01–B08) НЕ завершён. Текущая ветка — work.

- `GET /` в dev: HTTP 200, проверены текст страницы, кнопка nsuhw и сообщение,
  что сбор данных не ведётся.
- `GET` Mailpit API: HTTP 200. Отправка писем приложением не проверялась.
- SQL первой миграции выполнен в транзакции с ROLLBACK в PostgreSQL: успешно.
  Это не применение миграции через Prisma и не проверка соответствия модели SQL.
- `npm audit --audit-level=high` после обновления Prisma: код 0, высоких/критических

  успешный CI не заявляется. Защитные проверки и контрольные суммы не отключались.

## Блокер среды и следующий шаг

В черновик сетевых настроек сохранён binaries.prisma.sh. Сейчас этот домен отсутствует
в применённой политике; требуется сохранить настройки и опубликовать среду.
Это не проблема GitHub-авторизации или пароля БД. Не обходить proxy и не отключать
проверку checksum. После применения в корне репозитория:

1. `npm ci`, затем `npm run db:generate`.
2. `docker compose up -d --wait`, затем `npm run db:migrate`.
3. Проверить соответствие миграции schema.prisma (Prisma migrate diff), исправить
   обнаруженное расхождение до продолжения, не выполнять reset пользовательской БД.
4. Дважды `npm run db:seed`, проверить отсутствие дублей демонстрационных справочников.
5. `npm run lint`, `npm run typecheck`, `npm run test:db`, `npm run build`.
6. Запустить приложение и проверить `/` и `/api/health` с доступной и недоступной БД.
7. Обновить фактические исходы здесь и в TASKS.md; затем продолжить B04–B07:
   политика доступа/аудит, регистрация/согласия/email, сессии/восстановление, MFA/назначения.

Процессы не переживают новую облачную задачу: сервисы запускаются через Compose,
приложение — npm run dev. Существующий checkout использовать без создания worktree.
Не считать непроверенные команды успешными и не объявлять среду готовой к production.

## Перед последующими предметными этапами

- Перед nsuhw: подтвердить способ проверки принадлежности старого аккаунта, импорт
  доступных секретов и ручное создание новых аккаунтов оператором nsuhw. Генерация
  строки пароля у нас не создаёт аккаунт там. Не сопоставлять аккаунты по ФИО.
- Перед результатами: подтвердить шаблон CSV, значения и пропуски баллов по задачам;
  формулы расчёта не выдумывать.
- До production: заменить юридические заглушки, определить оператора и процедуру
  для несовершеннолетних, провайдеров, ключи, сроки и проверить восстановление.

После каждой части работы обновлять DECISIONS, TASKS и HANDOFF и отправлять изменения
в Git. PRD сохранён без изменений. `.env`, node_modules, файлы БД и реальные данные
не должны попадать в коммиты.
