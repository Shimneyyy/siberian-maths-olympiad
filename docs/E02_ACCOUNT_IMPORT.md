# E02/E03 — импорт готовых аккаунтов nsuhw

9 ноября 2026 пользователь подтвердил CSV «ID пользователя ЛК, логин nsuhw,
пароль nsuhw», доступ только главному назначенного года, предпросмотр и частичное
применение верных строк. Все дубли ошибочны, существующие аккаунты не заменяются,
исходный файл не сохраняется. Только синтетические данные.

Технический контракт реализации: UTF-8 с необязательным BOM, запятая,
кавычки CSV, точные заголовки `ID пользователя ЛК,логин nsuhw,пароль nsuhw`.
Размер до 512 КиБ, до 1000 строк, пароль 1–128 символов без управляющих символов;
пароль не обрезается и не нормализуется. Это защитные лимиты, не требование nsuhw.
Неверное обрамление CSV отвергает файл целиком, ошибки данных — конкретные строки.

Владелец — подтверждённый студент с участием выбранного года, только @example.test.
Существующий prepared-account или любая legacy-декларация запрещают замену.
ФИО не используется для сопоставления. Дубли userId и логина (без учёта регистра
для защиты пространства новых записей) отвергаются все, даже если одна строка неверна.
Существующее написание внешних логинов не изменяется.

Предпросмотр не возвращает пароли, содержимое CSV или чужие логины: только номера
строк, доступные в году имена участников, фиксированные коды ошибок и fingerprint.
Подтверждение требует текущий пароль ЛК, общий лимит reauth и отдельную отметку,
что это уже действующие данные, проверенные главным у ответственного за nsuhw.
Импорт не создаёт аккаунт на внешнем сайте и не подтверждает такую интеграцию.

Применение повторно проверяет права/участия/пространство логинов под блокировками.
Существующая генерация, legacy-подача и импорт используют общий User/namespace lock.
Идемпотентный UUID привязан к автору, году и HMAC исходника. HMAC использует
BETTER_AUTH_SECRET с отдельным purpose: plaintext CSV/пароль и обычный SHA пароля
не сохраняются. Смена этого секрета требует отдельного плана (он также защищает TOTP).
Сбой БД/ключа/аудита/outbox откатывает весь batch; частичность только для ошибок строк.

Внешние пароли шифруются существующим E01 с отдельным ключом и AAD; сохраняется
подтверждение источника. Затем собственная выдача E06 работает с прежними проверками.
Email — только уведомление о доступности, без логинов, паролей и вложений.
Исходник существует в памяти формы/запроса и очищается после успеха; файл на компьютере
ответственный удаляет сам. Нет серверного временного CSV, URL или browser storage.

E02/E03 реализованы: account-import-csv.ts/account-imports.ts, два POST API и
/cabinet/nsuhw-import. Миграция 24 добавляет неизменяемый batch без plaintext.
Проверки: lint/typecheck, 109/109 общего DB/service-набора (5 новых импортных),
communications Chromium/HTTP/SMTP 1/1, build/check:build и пустой schema diff.
Браузер загрузил настоящий синтетический CSV, показал 1 верную/1 ошибочную строку,
применил только верную и очистил file input. Проверены роль/год/CSRF/body-limit/
подмена/отзыв; уведомление реально доставлено в Mailpit без пароля.
Сервисные тесты проверяют round-trip E06, отсутствие plaintext в batch/audit/outbox,
дубли user/login, immutable SQL, stale/replay, сбой audit/outbox и конкурентный UUID.
HTTP auth 6/6 относится к F02b; отдельно в этой задаче не повторялся.
Новых зависимостей нет; production-KMS и реальный nsuhw не проверены.
Production по-прежнему запрещён; совместимость с настоящим nsuhw не проверяется.
