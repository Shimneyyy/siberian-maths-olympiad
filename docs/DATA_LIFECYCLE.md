# Жизненный цикл данных учебного контура

Решение пользователя от 9 ноября 2026:

| Данные | Правило |
| --- | --- |
| Результаты | Бессрочные записи в профиле: год, баллы, номинация из существующего поля «Приз» |
| Дипломы | Бессрочно, включая сохранение версий; собственная выдача только текущей опубликованной версии |
| Аккаунт и участия | Автоматического удаления нет |
| Аудит | Один календарный год; граница срока сохраняется, удаляется только более старое |
| Резервные копии | 30 дней, только управляемые копии учебного инструмента |
| Прежние обращения | Хранятся для ручного разбора оператором |

Прежние предложения о пяти годах для результатов/дипломов отменены этим решением.
Реальные ПДн запрещены; бессрочное хранение требует проверки правового основания
оператором перед production. Юридические заглушки не являются таким основанием.

## Личная история и архив обращений

В профиле есть ссылка «Моя история результатов за все годы»: только собственные
опубликованные записи, по 25 на странице, год по убыванию. Итоговые скрывают
предварительные только своего года. Ноль отличается от отсутствия оценки;
номинация не вычисляется и берётся из «Приз». Дипломы доступны отдельной ссылкой.
Ни обращение, ни очистка аудита не удаляют результаты, дипломы, участия или аккаунт.

Форма обращения и публичный API удалены. Старые записи доступны оператору.

Оператор с локальным доступом работает только с синтетической loopback-БД:

```sh
DEMO_REGISTRATION=true npm run data:lifecycle -- requests
# Только после фактического ручного рассмотрения вне системы:
DEMO_REGISTRATION=true npm run data:lifecycle -- reviewed <UUID-обращения> --confirmed-external-review
```

Команда reviewed фиксирует факт внешнего рассмотрения, не одобрение удаления и
не отмену участия/публикации. ФИО/email, текст решения и секреты не печатаются.
TECHNICAL_ADMIN/CHIEF_ORGANIZER не получают новых предметных прав из роли.
До production нужен реальный оператор, проверка личности/полномочий заявителя,
сроки ответа и журнал решений во внешней утверждённой процедуре.

## Аудит и копии

```sh
# План без изменения данных:
DEMO_REGISTRATION=true npm run data:lifecycle -- audit
# Явное применение плана к текущему времени:
DEMO_REGISTRATION=true npm run data:lifecycle -- audit --apply
```

Удаление аудита и новая квитанция с числом/границей выполняются транзакционно:
сбой квитанции откатывает удаление. Будущую дату CLI задать нельзя. Нельзя применять
команду к production или удалённой БД. Локальная эксплуатация должна запускать её
ежедневно; расписание production ещё не установлено. После восстановления старой
копии обработать внешние обращения и повторить истечение аудита до открытия доступа.

Управляемые учебные backup-artifacts удаляются по 30-дневному сроку отдельным
инструментом проверки копий, не через удаление всех .local/ или файлов дипломов.
Не удалять чужие/неизвестные копии, keyring или бессрочные PDF. Production backup
scheduler и фактическое истечение копий выбираются с провайдером до запуска.

## F01b — управляемые копии

DemoBackupStore и backup:retention реализуют 30 дней для аутентифицированных
учебных snapshot. По умолчанию только план; --apply удаляет лишь проверенные
UUID-каталоги этого инструмента. Неподписанный/повреждённый manifest, неизвестный
файл, открытые права, симлинк или потерянный ключ дают отказ. Master-key и
актуальные копии сохраняются. Граница 30 дней и отсутствие удаления до неё
проверены mock-clock тестом, реальные данные не использованы.
Команды/лимиты и restore-drill — [OPERATIONS.md](OPERATIONS.md).

## Ручная изоляция orphan-файлов

[files:orphans](../scripts/file-orphans.ts) работает только в локальном synthetic
режиме. Срок не установлен автоматически: оператор явно передаёт --min-age-hours N
(N ≥ 1). По умолчанию команда лишь считает кандидатов. Для перемещения нужны
--apply --confirmed-quiesced после остановки app/worker. Инструмент также захватывает
обе блокировки подготовки, проверяет приватные права и обычные UUID quarantine-файлы.
Любая ссылка DiplomaItem, включая неопубликованную/историческую, сохраняет файл.

Файлы без ссылок старше выбранной границы перемещаются в соседний приватный
orphan-staging/<UUID> с прежним opaque именем; окончательного удаления нет.
Аудит содержит только размер/hash. При обычной ошибке перемещения откатываются
по возможности; crash не даёт атомарности файловой системы и БД. До восстановления
оператор проверяет исходный ключ и отсутствие нового файла. Срок окончательного
удаления, расписание и production-процедура остаются несогласованными.

Уточнение 21 ноября: неудачная загрузка не создаёт автоматическое обращение
студента. Автоматическое удаление orphan не включено, восстановимая изоляция
остаётся ручной процедурой оператора по [ADR-013](decisions/ADR-013-isolated-file-inspection.md).
